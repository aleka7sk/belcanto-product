## 6. Migration/data compatibility plan + общие границы (Phase 0)

**Миграции — additive, checksum-protected (embed.go ledger), advisory-locked.** План нумерации:
- `000003_identity_security`: verified_contacts (phone/email, verified_at), twofa_factors (totp secret digest, enabled_at, recovery codes digests), account_security_events (проекция audit для Security Center), biometrics_capability (client-declared, server хранит только флаг enrollment), re-auth уже есть (owner reauthentication) → обобщить step-up.
- `000004_policies_consents`: policy_versions (kind, version, effective_from, body_ref), policy_acceptances, privacy_settings, data_export_requests, account_deletion_requests (cancel window; без авто-удаления — DEC-104 BLOCKED), server_config (namespaced key/value: waitlist TTL DEC-101, quiet-hours bypass DEC-106, moderation SLA DEC-107, late-cancellation DEC-102 default off).
- `000005_rooms_core_lessons`: rooms; core_lesson_series (format individual|group, teacher, room, weekly recurrence, duration, version); core_lesson_occurrences (6 статусов, room/teacher override, version); core_lesson_enrollments (constraint: individual=1, group<=3 на occurrence, DB CHECK+trigger); attendance_records (versioned). Data migration legacy `lessons`: participants<=3 → ad-hoc occurrences (1→individual, 2-3→group); >3 → RAISE EXCEPTION (production-данных нет; guard детерминирован); legacy-таблицы сохраняются read-only (история неизменяема).
- `000006_events_rsvp`: event_categories (data-driven), event_series (weekly recurrence, capacity, host, room), event_occurrences (override/exception, capacity >= confirmed CHECK), event_rsvps (unique student+occurrence, статусы), waitlist_entries (позиция), spot_offers (server expiry, idempotent confirm); атомарность last seat: advisory lock (tenant, occurrence) + `WHERE confirmed_count < capacity` guard.
- `000007_reschedule_requests`; `000008_journal_progress` (lesson_journals draft/published/corrected + journal_versions, progress_evidence, progress_reviews baseline|pulse|deep, goals, achievements, repertoire_items + history); `000009_homework_practice` (homework_assignments/steps, practice_submissions versioned, media_objects + upload sessions); `000010_community` (spaces/posts/threads/comments/chats scoped, reports, moderation_actions, blocks — tombstone deletes); `000011_notifications` (notifications, preferences, delivery_attempts, dead_letter; outbox worker); `000012_analytics_observability` (при необходимости — privacy-safe event journal).

**Общие границы:**
- Pagination: server-backed cursor (`?cursor=&limit=`, opaque base64 of (sort key, id), default/max limit из config) — для растущих списков (onboarding queue, students, occurrences, activity, community, audit). Существующие bounded-списки не ломаются.
- Ошибки/идемпотентность/версии: переиспользуются существующие ErrorCode/envelope/idempotency_records/expected-version паттерны; scope на операцию.
- Audit/outbox: атомарная запись сохраняется; ДОБАВИТЬ outbox worker (long-poll goroutine в cmd/api): claim batch FOR UPDATE SKIP LOCKED → adapter dispatch → published_at/attempt_count/dead-letter; notification delivery = первый consumer.
- Media: storage adapter interface (local dev impl под gitignored каталог + production S3-совместимый контракт), короткоживущие signed URLs (HMAC token + TTL), URLs не попадают в audit/outbox; upload sessions с resumable/retry.
- 2FA: TOTP (RFC 6238, otpauth URI), секреты только digest/encrypted at rest, recovery codes hashed; staff 2FA required (HOF-12) через policy flag.
- Time: UTC storage, RFC3339 boundary, IANA Asia/Almaty display/recurrence (уже в контрактах).
