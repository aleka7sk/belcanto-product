# CLAUDE.md — контракт AI-агента

Этот репозиторий содержит **продуктовую документацию** Belcanto Product.

Прикладного или продуктового кода реализации здесь **сейчас нет**. Локальный инструментарий репозитория — средства поддержания и проверки источника истины (`.claude/scripts/`) — **допустим**. Будущее размещение мобильной и серверной реализации **не определено**.

Ты работаешь не с кодовой базой, а с **источником истины о продукте**. Ошибка здесь дороже ошибки в коде: она не падает при запуске, а тихо расходится с остальной документацией.

## Пять правил, нарушать которые нельзя

**1. Одно понятие — один документ.**
Перед тем как что-то написать, найди владельца понятия в [`meta/007-ownership-map.md`](meta/007-ownership-map.md). Если владелец есть — писать нужно туда. В остальных местах ставится ссылка, а не пересказ. См. [`meta/004-anti-duplication-rules.md`](meta/004-anti-duplication-rules.md).

**2. Знание только в разделе 6.**
Разделы 1–5 каждого документа — контракт (Purpose, Owner, Dependencies, Reading Order, Validation Rules). Продуктовое знание в них — ошибка. См. [`meta/003-document-template.md`](meta/003-document-template.md).

**3. Каскад обязателен.**
Изменив документ, открой каждый документ из его поля `Required By` и определи его состояние: не затронут / требует правки / противоречит. Изменение без каскада не завершено. См. [`meta/009-contribution-workflow.md`](meta/009-contribution-workflow.md).

**4. Противоречие не разрешается молча.**
Нашёл расхождение — примени алгоритм [`meta/002`](meta/002-authority-model.md), раздел 6.3. Если алгоритм говорит «остановиться» — остановись, пометь оба документа `Status: Disputed`, открой запись в [`governance/decisions/000-decision-log.md`](governance/decisions/000-decision-log.md) и спроси владельца. Не выбирай вариант сам.

**5. Не придумывай факты о школе.**
Всё, что касается реальной работы школы Belcanto, берётся только из `school/` или из подтверждённого источника. Неподтверждённое утверждение либо помечается как гипотеза, либо попадает в [`school/007-open-questions.md`](school/007-open-questions.md). Правдоподобная выдумка в этом репозитории неотличима от факта — и это главный риск.

## Направление знания

```
school → product → language → domain → experience → features → design → roadmap
факты     смысл      слова      модель    структура    поведение   форма    порядок
```

Документ ссылается на свой или предыдущий слой. Ссылка вперёд допустима только в поле `Required By`.

Если решение хочется принять в нижнем слое — почти всегда оно принадлежит верхнему.

**Принятый продуктовый поток** ([`docs/project/project-constitution.md`](docs/project/project-constitution.md), PD-0019, PD-0027):

```
Business Goals → Capability Map → Language → Domain → Experience → Design → Implementation
```

- Карта способностей выводится из **принятых** Бизнес-целей;
- `domain/` **не является свидетельством** для обнаружения способностей;
- производство `language/` и `domain/` не начинается, пока Карта способностей не достигнет статуса, требуемого [`meta/012`](meta/012-authoring-binding.md).

## Документ не пишут напрямую

Продуктовый документ производится конвейером ([`meta/standard/017-authoring-pipeline.md`](meta/standard/017-authoring-pipeline.md)). Файл появляется только на стадии P4; проза — на P5.

```
P0 Запрос → P1 Область → P2 Источники → P3 Утверждения → P4 Структура → P5 Черновик
                                          ↑ ГЛАВНЫЕ ВОРОТА                    ↓
P9 Канонизация ← P8 Интеграция ← P7 Рецензия ← P6 Самопроверка ←──────────────┘
```

**Правило, которое касается тебя больше всего.**

Прежде чем написать хоть одну фразу содержания, реестр утверждений (P3) должен быть утверждён ролью. Реестр — плоский перечень: каждое утверждение одним предложением, с классом (A выведенное · B решённое · C наблюдённое · D определяющее) и конкретным источником.

Затем:

| Ситуация | Что делать |
|----------|------------|
| Пишешь прозу по утверждённому реестру | **разрешено полностью** — суждение израсходовано на P3 |
| По ходу письма понял, что нужно ещё одно утверждение | **НЕ дописывай.** Возврат на P3 |
| Утверждению не нашёл источника | открытый вопрос, не правдоподобный текст |
| Стадию отклонили дважды подряд | третья попытка запрещена — сузить, разделить или эскалировать |
| Отклонили — куда возвращаться | на стадию, где дефект **возник**, а не на предыдущую |

**Где ты наиболее полезен:** P2 (сбор и проверка источников), P3 (извлечение и классификация утверждений), P6 (проверки), P8 (каскад и реестры).

**Что остаётся человеку:** утверждение реестра (P3), вердикт рецензии (P7), канонизация (P9).

**Наполнение скелетов начинается с P2, а не с P0** — 68 документов уже прошли P0–P4, их разделы 1–5 и есть карта области. Классы, роли и профили риска — [`meta/012-authoring-binding.md`](meta/012-authoring-binding.md).

## Классы изменений

Определяют, что ты можешь применить сам, а что только предложить ([`meta/standard/008-agent-change-protocol.md`](meta/standard/008-agent-change-protocol.md), раздел 6.2):

| Класс | Что это | Твоё право |
|-------|---------|------------|
| **A** | опечатка, форматирование, починка ссылки | применять |
| **B** | добавление содержания в пределах зоны документа, в состояние `Draft` | применять |
| **C** | изменение или отмена существующего утверждения; несколько документов | **только предложение** |
| **D** | документ `Canonical`, реестр, решение, документ стандарта или привязки | **только предложение** |

При сомнении между классами — выбирай **более высокий**. Класс определяется последствиями, а не объёмом правки: одно слово, отменяющее правило, — это класс C.

Предложение оформляется по форме из раздела 6.4 протокола и всегда затрагивает **одно** понятие.

## Что запрещено делать всегда

Полный список — [`meta/standard/008-agent-change-protocol.md`](meta/standard/008-agent-change-protocol.md), раздел 6.5. Основное:

- создавать второе определение существующего термина;
- изменять принятый PDR — он неизменяем; отмена выполняется новым PDR;
- удалять документы: история продукта неизменяема, устаревшее помечается `Superseded`;
- переводить документ в `Approved`, `Canonical` или `Superseded` — это право владельца, не агента;
- вносить изменение класса C или D напрямую, минуя предложение;
- умалчивать о непроверенном — перечень непрочитанного и неподтверждённого обязателен и не может быть пустым по умолчанию;
- изменять `product/000-product-overview.md` или другой документ ранга ≤ 30 без PDR;
- писать конкретные значения цвета, размера, длительности где-либо, кроме [`design/011-design-tokens.md`](design/011-design-tokens.md);
- использовать слова из [`language/004-forbidden-terms.md`](language/004-forbidden-terms.md);
- оставлять относительные даты («недавно», «скоро») — только абсолютные;
- помещать правило только в диаграмму или изображение.

## Порядок работы над задачей

```
1. Определить понятие  → meta/007-ownership-map.md
2. Прочитать владельца + всё из его Depends On
3. Проверить, не существует ли знание уже где-то ещё
4. Изменить ОДИН документ, только раздел 6
5. Повысить Version, обновить Last Updated и «Историю изменений»
6. Пройти каскад Required By
7. Обновить реестры: meta/001-reading-order.md, meta/007-ownership-map.md
8. Проверить по meta/006-validation-rules.md, уровни 1–3
9. Изменён смысл документа ранга ≤ 30 → создать PDR
```

## Форма нового документа

Копируется из [`meta/003-document-template.md`](meta/003-document-template.md). Обязательны все поля frontmatter, включая `Defines` и `Must Not Define`.

Документ без `Defines` не имеет права на существование: он ничем не владеет и, значит, дублирует что-то другое.

Новый документ создаётся **последним средством** — сначала проверь, нет ли подходящего существующего ([`meta/004`](meta/004-anti-duplication-rules.md), правило D7).

## Статусы: на что можно опираться

| Status | Опора |
|--------|-------|
| `Canonical` | да, безусловно |
| `Approved` | да, в пределах зоны документа |
| `Review` | с оговоркой, отметив риск |
| `Draft`, `Scaffold` | нет |
| `Disputed` | нет — до принятия PDR |
| `Superseded` | нет |

Прежние значения `Accepted` и `Deprecated` выведены из употребления миграцией M-0001 ([`meta/010-migration-register.md`](meta/010-migration-register.md)). Встретив их в унаследованном документе, читай как `Approved` и `Superseded`; при записи используй только новые.

Большая часть репозитория сейчас в статусе `Scaffold`: контракт документа задан, содержание не написано. Не выдавай отсутствующее содержание за существующее.

## Навыки — приоритет и ворота

- **Корпус выше навыка.** При расхождении навыка с документом в состоянии `Approved` действует документ; навык считается дефектным и подлежит исправлению. Навыки не владеют продуктовой истиной.
- **Сначала ворота ценности.** Перед созданием любого постоянного артефакта применяется навык `artifact-value-gate`. Артефакт, который не снижает неопределённость реализации и не позволяет реализацию напрямую, не создаётся.
- **Проверка механическая.** Детерминированные проверки выполняет `.claude/scripts/validate.py` или `/validate`, а не рассуждение.
- **Стадия — из репозитория.** Работа, привязанная к стадии, читает фактические значения `Status` и различает три разных вопроса: разрешено ли производство, каков предельный допустимый статус, разрешена ли приёмка.
