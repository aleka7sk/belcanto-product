> Конвейер описан в [`meta/standard/017-authoring-pipeline.md`](standard/017-authoring-pipeline.md), профили классов — в [`meta/standard/018-document-class-profiles.md`](standard/018-document-class-profiles.md).

## 5. Validation Rules · Правила валидации

1. Каждый каталог репозитория отнесён ровно к одному классу документов, либо покрыт правилом умолчания раздела 6.2.
2. Каждая стадия P0–P9 имеет назначенную роль для каждого класса.
3. Ни одна роль не совмещает стадии P5 и P7 для одного документа.
4. Каждый артефакт конвейера имеет определённое место хранения.

## 6. Content · Содержание

### 6.1. Каталоги и классы

| Каталог | Класс | Профиль риска |
|---------|-------|---------------|
| `school/000…007` | **C2 Наблюдение** | реконструкция вместо подтверждённого |
| `product/000`, `001`, `002`, `006`, `007`, `008`, `009`, `010` | **C1 Замысел** | утверждение, не запрещающее ничего |
| `product/003` персоны | **C1 Замысел** (источники класса C2) | описание, выдаваемое за решение |
| `product/004` ключевые концепции | **C1 Замысел** | определение слова вместо идеи → принадлежит `language/` |
| `language/001`, `003`, `004` | **C3 Определение** | понятие занято другим документом |
| `language/002`, `005` | **C1 Замысел** | правило без запрета |

| `experience/001`, `002`, `004…010` | **C5 Опыт** | шаг без источника; разрыв в пути |
| `features/catalog/**` | **C6 Поведение** | правило, принадлежащее модели |
| `design/001…011` | **C7 Форма** | величина вне `design/011` |
| `roadmap/**` | **C8 План** | единица вне реестра; нарушенный порядок зависимостей |
| `experience/003`, `features/000`, `governance/decisions/000`, `meta/001`, `meta/007`, `meta/010`, `assets/references/000` | **C9 Реестр** | описание вместо идентификатора |
| `meta/**`, `governance/000…002`, `ai/**` | **C1 Замысел** | процессное правило без запрета |

**Правило умолчания.** Каталог, не перечисленный выше, относится к классу по вопросу, на который отвечает (DES-018, раздел 6.3). Отсутствие в таблице — повод её дополнить, а не повод обойтись без класса.

### 6.4. Утверждающие и рецензенты по классам

| Класс | Утверждает реестр утверждений (P3) | Рецензирует (P7) |
|-------|------------------------------------|------------------|
| C1 Замысел | Product Owner | Education Lead или Documentation Lead |
| C2 Наблюдение | Education Lead | Product Owner + носитель процесса |
| C3 Определение | Education Lead | Domain Architecture Lead |
| C4 Модель | Domain Architecture Lead | Education Lead **и** Technical Lead |
| C5 Опыт | Product Owner | Design Lead + Education Lead |
| C6 Поведение | Product Owner | Design Lead; при затрагивании модели — Domain Architecture Lead |
| C7 Форма | Design Lead | Product Owner; доступность — независимая проверка |
| C8 План | Product Owner | Technical Lead |
| C9 Реестр | Documentation Lead | владеющая роль описываемого слоя |

**Правило несовмещения.** Одна роль НЕ ДОПУСКАЕТСЯ ведущей стадию P5 и рецензирующей P7 для одного документа. При совпадении по таблице рецензентом становится Documentation Lead с проверкой формы, связей и прослеживаемости; документ помечается как проверенный частично (DES-003, раздел 6.4).

Совпадение будет частым: ролей семь, а исполнителей меньше. Правило не устраняет проблему, а делает её видимой в отчёте вместо того, чтобы она разрешалась молча.

### 6.5. Порядок производства слоёв

Из порядка выводимости классов (DES-018, раздел 6.5) следует порядок для этого репозитория:

```
school/  ──▶  product/  ──▶  language/  ──▶  domain/  ──▶  experience/  ──▶  features/  ──▶  roadmap/
                                                                │
                                                                └──▶  design/
```

1. Документ НЕ ДОПУСКАЕТСЯ к стадии P2, если его источники находятся в состоянии ниже `Approved`.
2. Параллельное производство `experience/` и `domain/` НЕ СЛЕДУЕТ: опыт будет переписан вслед за моделью.
3. `design/` производится после `experience/`, но параллельно `features/` — ДОПУСКАЕТСЯ.
4. Реестры (C9) производятся вместе с первым описываемым объектом, а не заранее.

**Текущее следствие.** `domain/` находится в состоянии `Approved` и наполнен; `language/` — в состоянии `Scaffold`. Порядок нарушен исторически: модель произведена раньше определений. Это зафиксировано как миграция **M-0003** ([`meta/010-migration-register.md`](010-migration-register.md)) и означает, что производство `experience/` начинается только после разграничения владения терминологией.

### 6.6. Хранение артефактов

| Артефакт | Где хранится |
|----------|--------------|
| Заявка на производство (P0) | в описании изменения, породившего документ |
| Карта области (P1) | раздел 5 создаваемого документа + описание изменения |
| Досье источников (P2) | поле зависимостей документа с закреплёнными версиями |
| **Реестр утверждений (P3)** | **таблица вывода в конце раздела 6 документа** |
| Отчёт самопроверки (P6) | описание изменения |
| Вердикт рецензии (P7) | описание изменения |
| Запись интеграции (P8) | описание изменения, поле каскада |
| Запись регистрации (P9) | `meta/007-ownership-map.md`, `meta/001-reading-order.md` |

**Решение о реестре утверждений.** Отдельный файл на документ не заводится. Реестр утверждений хранится как таблица вывода (DES-006, раздел 6.4): она содержит те же поля — раздел, класс утверждения, источник, версия источника — и живёт вместе с документом.

Обоснование: отдельный файл реестра пришлось бы синхронизировать с документом вручную, и он разошёлся бы с ним при первом же изменении. Совмещение делает расхождение невозможным по построению.

**Следствие для стадии P3.** До создания файла документа реестр утверждений ведётся во временной форме в описании изменения и переносится в таблицу вывода на стадии P4.

### 6.7. Сокращённый конвейер в этом репозитории

Сокращение по DES-017, раздел 6.12, ДОПУСКАЕТСЯ при выполнении условий:

| Условие | Значение |
|---------|----------|
| Документ производится одной ролью в один приём | артефакты P0–P2 объединяются в одну запись |
| Класс C9 Реестр | стадия P3 сводится к правилам ведения реестра |
| Изменение класса `PATCH` | вход на P5, стадии P0–P4 не выполняются |
| Документ в состоянии `Scaffold` наполняется впервые | карта области P1 уже существует — раздел 5 документа; повторно не составляется |

Последняя строка существенна: **68 документов репозитория уже прошли стадии P0–P4.** Их разделы 1–5 являются картой области и скелетом. Производство каждого из них начинается со стадии **P2**, а не с P0.

### 6.8. Что даёт конвейер этому репозиторию сейчас

| Свойство | Обеспечивается |
|----------|----------------|
| Скелеты не придётся переделывать | стадии P0–P4 для них пройдены; зона и правила завершённости объявлены |
| Наполнение начинается с источников | вход на P2 |
| Рамка проверяется до прозы | ворота P3, утверждающий по таблице 6.4 |
| Проза может писаться агентом | суждение израсходовано на P3 (DES-017, раздел 6.14) |
| Порядок наполнения задан | раздел 6.5 |
| Нарушение порядка видно | M-0003 зафиксирована |
