# Модель авторитета документов

> Противоречия в документации неизбежны. Недопустимо другое — **неопределённость**, какой документ главный.
>
> Этот документ даёт ответ, который всегда однозначен и не зависит от того, кто спрашивает.

---

## 1. Purpose · Назначение

Дать детерминированное правило: при расхождении двух документов — какой из них истина, а какой подлежит исправлению.

## 5. Validation Rules · Правила валидации

1. Каждый документ, находящийся под контрактом документа, имеет поле `Authority Rank` со значением, зарегистрированным в таблице 6.1.
2. Каждый такой документ имеет поле `Authority Scope`.
3. Ранг документа, принадлежащего слою L0–L11, равен рангу его зарегистрированного слоя.
4. Ранг документа области авторитета `Project` равен рангу этой зарегистрированной области.
5. Индивидуальные исключения по отдельным документам запрещены.
6. Для любой пары документов алгоритм 6.3 даёт однозначный результат.

## 6. Content · Содержание

### 6.1. Ранги авторитета

**Меньше ранг — выше власть.**

| Ранг | Область авторитета / слой | Зона авторитета | Не имеет власти над |
|------|---------------------------|-----------------|---------------------|
| **0** | `governance/decisions/` | Изменяет любой документ любого слоя | — |
| **3** | `meta/standard/` | Процесс производства документации | продуктовым содержанием, моделью слоёв |
| **4** | `Project` · `docs/project/` | Инженерная философия проекта, порядок архитектурного потока, правило выбора простейшей архитектуры, роль архитектора проекта — в пределах `Authority Scope` Конституции | записанными решениями, стандартом производства документации, привязкой и формой документов, продуктовой истиной, содержанием `language/`, `domain/`, `experience/`, `features/`, `design/` |
| **5** | `meta/` | Форма, порядок, правила документов | продуктовым содержанием, процессом производства |
| **10** | `product/` | Смысл, границы, цели, продуктовые правила | — |
| **20** | `language/` | Определения терминов | смыслом продукта |
| **30** | `domain/` | Семантика модели: сущности, события, политики | терминами, смыслом продукта |
| **40** | `experience/` | Структура, навигация, сценарии | моделью, терминами |
| **50** | `features/` | Поведение конкретных возможностей | структурой, моделью |
| **60** | `design/` | Форма: вид, движение, тон, доступность | поведением, структурой |
| **70** | `roadmap/` | Объём и последовательность релизов | содержанием чего-либо |
| **90** | `school/` | Факты о текущей реальности школы | целевым состоянием продукта |
| **100** | `ai/` | Поведение AI-агентов | всем продуктовым |
| **110** | `assets/` | Ничем | всем |

Строка `Project` — **область авторитета**, а не слой документации: она находится вне L0–L11 и слоя L12 не образует ([`meta/000`](000-documentation-system.md), раздел 6.2.2). Основание регистрации — **PD-0028**.

### 6.2. Два вида власти

Ранг — не единственный критерий. Работают два правила, и **зона важнее ранга**.

**Зона авторитета.** Документ авторитетен **только по вопросам своего слоя или своей области авторитета**. `product/000` — главный документ репозитория, но он не определяет длительность анимации. Если он это делает, ошибка в `product/000`, а не в `design/007`.

**Ранг.** Применяется, когда два документа спорят **внутри одной зоны** или когда зона неочевидна.

### 6.3. Алгоритм разрешения конфликта

Настоящий раздел закрывает требование **B2** стандарта: полный порядок разрешения. Механика **обнаружения** расхождений принадлежит [`meta/standard/009-conflict-detection.md`](standard/009-conflict-detection.md) и здесь не повторяется.

Обнаружено расхождение между документами **A** и **B**:

```
1. Определить, о ЧЁМ спор → к какому слою или области авторитета относится предмет спора.

2. Есть ли принятый PDR по этому предмету?
   ДА  → PDR является истиной. Оба документа приводятся к PDR. КОНЕЦ.
   НЕТ → шаг 3.

3. Предмет спора относится к зоне ровно одного из документов?
   ДА  → истина в нём. Второй документ исправляется. КОНЕЦ.
   НЕТ → шаг 4.

4. Один документ объявляет предмет в поле Defines?
   ДА  → истина в нём (правило владельца смысла). КОНЕЦ.
   НЕТ → шаг 5.

5. Ранги различаются?
   ДА  → истина в документе с меньшим рангом. КОНЕЦ.
   НЕТ → шаг 6.

6. ОСТАНОВИТЬСЯ. Конфликт не разрешим документацией.
   Открыть PDR в governance/decisions/.
   Пометить оба документа как Status: Disputed.
   Не выбирать вариант самостоятельно.
```

Шаг 6 обязателен и для человека, и для AI-агента. Самостоятельный выбор варианта при равном авторитете — нарушение (см. [`meta/standard/008-agent-change-protocol.md`](standard/008-agent-change-protocol.md), раздел 6.5, запрет N12).

### 6.4. Особый статус `school/`

`school/` имеет высокий ранг (90) и при этом является фундаментом. Противоречия нет: слой **описательный**.

- По вопросу «как в школе происходит сегодня» — `school/` есть истина, и `product/` не может её опровергнуть.
- По вопросу «как должно быть в продукте» — `school/` не имеет голоса.

Расхождение между `school/` и `product/` чаще всего не ошибка, а **намеренное изменение реальности**. Такое расхождение фиксируется в PDR, а не «исправляется».

### 6.5. Особый статус `governance/decisions/`

Принятый PDR — единственный способ изменить смысл документа высокого ранга, включая `product/000-product-overview.md`.

- PDR **не переписывает** документ автоматически: он обязывает владельца обновить его.
- До обновления документа PDR уже является истиной.
- PDR никогда не удаляется. Отменённый PDR помечается как отменённый со ссылкой на заменяющий.

### 6.6. Самопровозглашение авторитета

`product/000-product-overview.md` содержит утверждение: «Если любой другой документ противоречит этому документу, приоритет имеет данный документ».

Это утверждение **действует** и согласовано с рангом 10 — но ограничено зоной по правилу 6.2. Оно означает: по вопросам смысла, границ и целей продукта `product/000` выше всех, кроме принятого PDR.
