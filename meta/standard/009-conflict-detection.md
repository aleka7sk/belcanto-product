# Обнаружение конфликтов

> Конфликт в документации редко выглядит как конфликт. Он выглядит как два разумных документа, каждый из которых прав в своей части.
>
> Поэтому стандарт не пытается их рассудить. Он делает две вещи: **находит расхождение автоматически** и **запрещает разрешать его молча**.

---

## 1. Purpose · Назначение

Обеспечить, чтобы расхождения между документами и конкурирующие изменения обнаруживались машиной, а не читателем, и чтобы обнаружение никогда не превращалось в самовольное разрешение.

## 6. Content · Содержание

### 6.1. Классы конфликтов

| Класс | Что расходится | Обнаружение |
|-------|----------------|-------------|
| **K1 · Владение** | два документа заявляют одно понятие | автоматическое |
| **K2 · Определение** | одно понятие определено по-разному в двух местах | полуавтоматическое |
| **K3 · Значение** | одна величина указана в двух местах | автоматическое |
| **K4 · Норма** | два нормативных утверждения об одном предмете несовместимы | человек |
| **K5 · Устаревание** | документ не обновлён после изменения источника | автоматическое |
| **K6 · Направление** | нижестоящий документ переопределяет вышестоящий | автоматическое |
| **K7 · Конкурирующее изменение** | два изменения одного места основаны на разных версиях | автоматическое |
| **K8 · Реальность и замысел** | описание существующего расходится с описанием целевого | человек |

**K8 — не всегда дефект.** Расхождение между тем, что есть, и тем, что задумано, может быть содержанием замысла. Стандарт требует не устранять его, а различать: расхождение объявленное — замысел, расхождение обнаруженное — конфликт.

### 6.2. Обнаружение отделено от разрешения

```
ОБНАРУЖЕНИЕ                      РАЗРЕШЕНИЕ
машина                           роль
непрерывно                       по процедуре привязки
не требует полномочий            требует полномочий
результат: факт расхождения      результат: записанное решение
```

Правила:

1. Настоящий документ определяет **только** обнаружение.
2. Порядок авторитета, по которому конфликт разрешается, ОБЯЗАНА задать привязка (DES-016).
3. Привязка ОБЯЗАНА обеспечить **полный порядок**: для любой пары документов и любого предмета спора результат либо однозначен, либо явно определён как «требуется решение роли».
4. Молчаливое разрешение НЕ ДОПУСКАЕТСЯ ни человеком, ни агентом. Устранение расхождения без записи скрывает причину, и расхождение возвращается.
5. Выбор варианта при равном авторитете НЕ ДОПУСКАЕТСЯ. Требуется записанное решение.

### 6.3. Автоматические детекторы

| # | Детектор | Что сравнивает | Класс |
|---|----------|----------------|-------|
| A1 | Двойное владение | заявки на владение всех документов | K1 |
| A2 | Понятие без владельца | реестр понятий против заявок | K1 |
| A3 | Определение вне владельца | форма определения понятия в документах, не владеющих им | K2 |
| A4 | Расхождение глоссы | краткие пояснения термина в разных документах | K2 |
| A5 | Дублирование величины | литералы величин вне документа-владельца значений | K3 |
| A6 | Устаревший каскад | версия зависимости выше отметки проверки (DES-006, раздел 6.7) | K5 |
| A7 | Обратное направление | зависимость, направленная в нижестоящий слой | K6 |
| A8 | Нарушение порядка | зависимость, стоящая позже в порядке чтения | K6 |
| A9 | Несовпадение базовой версии | базовая версия предложения ≠ текущая версия документа | K7 |
| A10 | Пересечение изменений | два открытых предложения к одному документу или разделу | K7 |
| A11 | Ссылка на спорное | ссылка на раздел документа в состоянии `Disputed` | K4 |
| A12 | Ссылка на выведенное из обращения | входящая ссылка на `Superseded` | K5 |
| A13 | Опора на непринятое | документ в `Canonical` зависит от документа ниже `Approved` | K5 |
| A14 | Просроченный документ | срок с последней ревизии больше интервала | K5 |

Детекторы A3 и A4 полуавтоматические: они выдают кандидатов, отбор выполняет человек. Ложные срабатывания здесь дешевле пропусков.

### 6.4. Обнаружение конкурирующих изменений

Конкурирующие изменения (K7) возникают всегда, где над корпусом работают несколько участников или несколько агентов.

**Механизм — базовая версия.**

1. Каждое изменение и каждое предложение ОБЯЗАНО фиксировать версию документа, на которой оно основано.
2. Перед применением базовая версия сравнивается с текущей.
3. Совпадение — изменение применяется.
4. Расхождение — изменение **не применяется**; требуется пересборка на текущей версии.

**Правило пересборки.** Пересборка ОБЯЗАНА выполняться заново от текущего состояния, а не механическим переносом правки. Изменение, внесённое в промежутке, могло сделать исходное намерение неверным — а не только неприменимым.

**Пересечение предложений.** Два открытых предложения к одному разделу ОБЯЗАНЫ быть упорядочены владельцем документа: одно принимается, второе пересобирается. Одновременное принятие НЕ ДОПУСКАЕТСЯ.

**Для агентов.** Агент, обнаруживший расхождение базовой версии, ОБЯЗАН остановиться и сообщить, а не применять изменение принудительно (DES-008).

### 6.5. Протокол объявления конфликта

```
1. ЗАФИКСИРОВАТЬ
   документ A, документ B, предмет расхождения,
   оба утверждения дословно, детектор или способ обнаружения.

2. КЛАССИФИЦИРОВАТЬ
   класс K1–K8.

3. ПРИМЕНИТЬ ПОРЯДОК АВТОРИТЕТА ПРИВЯЗКИ
   результат однозначен  → шаг 4
   результат «требуется решение» → шаг 5

4. ИСПРАВИТЬ
   привести проигравшую сторону к победившей,
   повысить версию, пройти каскад,
   зафиксировать факт и основание.

5. ЭСКАЛИРОВАТЬ
   пометить обе стороны состоянием Disputed,
   в спорной части каждого документа разместить блок:
       предмет расхождения, вторая сторона, номер открытого решения,
       указание, что часть недействительна;
   зарегистрировать в журнале решений привязки;
   ОСТАНОВИТЬСЯ.
```

Шаг 5 обязателен и для человека, и для агента.

### 6.6. Сроки

| Событие | Требование |
|---------|------------|
| Обнаружение | немедленная регистрация; отложенная регистрация НЕ ДОПУСКАЕТСЯ |
| Пребывание в `Disputed` | не дольше порога привязки |
| Превышение порога | эскалация роли, принимающей решения |
| Открытое предложение | не дольше порога привязки; далее подлежит пересборке |

Отсутствие срока превращает состояние `Disputed` в способ отложить решение навсегда, сохранив видимость управляемости.

### 6.7. Периодичность обнаружения

| Детекторы | Когда |
|-----------|-------|
| A1, A5, A7, A8, A9, A13 | при каждом изменении, до его приёма |
| A3, A4, A10, A11 | при каждом изменении, результат — предупреждение |
| A2, A6, A12, A14 | по расписанию, заданному привязкой |
| K4, K8 | при проверке содержания человеком (DES-004, уровень V3) |

### 6.8. Ложные срабатывания

1. Ложное срабатывание ОБЯЗАНО быть зарегистрировано с обоснованием, а не просто проигнорировано.
2. Повторяющееся ложное срабатывание — основание уточнить детектор, а не отключить его.
3. Отключение детектора ОБЯЗАНО оформляться отклонением в реестре отклонений привязки с указанием срока.

### 6.9. Что не является конфликтом

| Ситуация | Почему не конфликт |
|----------|--------------------|
| Разные аспекты одного понятия у разных документов | у каждого аспекта свой владелец |
| Описание существующего расходится с описанием целевого, и это объявлено | замысел, а не расхождение |
| Документ в `Draft` расходится с `Canonical` | черновик не является истиной |
| Разные формулировки одного правила | конфликт формы; устраняется ссылкой на владельца |
| Внешний источник противоречит корпусу | внешний источник не имеет авторитета над корпусом |
