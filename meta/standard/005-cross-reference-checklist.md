# Чек-лист перекрёстных ссылок

> Ссылка — это не удобство навигации, а несущая конструкция. Ею заменяется копирование знания, ею же строится граф, по которому вычисляется каскад изменений.
>
> Нетипизированная ссылка бесполезна для проверок: по ней нельзя понять, что делать при изменении цели.

---

## 1. Purpose · Назначение

Сделать ссылки машинно-осмысленными: чтобы по графу ссылок можно было вычислить порядок чтения, каскад обновлений, зону влияния изменения и наличие осиротевших документов.

## 5. Validation Rules · Правила валидации

1. Каждая ссылка в корпусе относится ровно к одному типу из раздела 6.1.
2. Каждый тип ссылки имеет правило разрешения и правило поведения при изменении цели.
3. Каждый пункт CR1–CR14 проверяем ответом «да / нет».

## 6. Content · Содержание

### 6.1. Типы ссылок

| Тип | Назначение | Объявляется | При изменении цели |
|-----|------------|-------------|--------------------|
| **R1 Зависимость** | источник, без которого документ не имеет смысла | метаданными | обязательна проверка документа |
| **R2 Каскад** | обратная сторона зависимости | метаданными | обязателен обход при изменении |
| **R3 Цитата** | дословный фрагмент чужого документа | в тексте, с атрибуцией | обязательна сверка цитаты |
| **R4 Указатель** | перенаправление к владельцу знания | в тексте | обязательно обновление цели |
| **R5 Реестровая** | связь по идентификатору внутри реестра | в реестре | обязательна сверка идентификатора |
| **R6 Навигационная** | помощь читателю, знание не переносит | в тексте | действий не требуется |
| **R7 Внешняя** | источник вне корпуса | через реестр внешних источников | обязательна проверка доступности |

Тип ссылки ОБЯЗАН быть определим: из метаданных, из позиции в реестре или из формы записи. Ссылка, тип которой неопределим, приравнивается к R6 и не участвует в вычислении каскада — то есть теряет всякую пользу для проверок.

### 6.2. Правила по типам

**R1 · Зависимость**

1. Объявляется в метаданных, а не только в тексте.
2. ОБЯЗАНА указывать на документ в том же или вышестоящем слое.
3. ОБЯЗАНА находиться раньше в порядке чтения.
4. Документ в `Canonical` НЕ ДОПУСКАЕТСЯ иметь зависимость от документа ниже `Approved`.
5. Число зависимостей СЛЕДУЕТ удерживать в пределах порога привязки. Превышение — признак превышения бюджета ответственности (DES-010).

**R2 · Каскад**

1. Объявляется симметрично каждой зависимости. Асимметрия — дефект.
2. Обход каскада ОБЯЗАТЕЛЕН при изменениях класса `MINOR` и `MAJOR`.
3. Для каждого элемента каскада фиксируется исход: не затронут / изменён / противоречит.
4. Исход «противоречит» передаётся в процедуру обнаружения конфликтов (DES-009).

**R3 · Цитата**

1. ОБЯЗАНА сопровождаться указанием документа-источника.
2. Объём НЕ ДОПУСКАЕТСЯ превышающим порог привязки. Цитата, заменяющая пересказ целого раздела, — копия, а не цитата.
3. Цитата нормативного утверждения ОБЯЗАНА фиксировать версию источника.
4. При повышении `MAJOR` источника все цитаты из него ОБЯЗАНЫ быть сверены.
5. Цитата НЕ ДОПУСКАЕТСЯ как способ обойти запрет дублирования.

**R4 · Указатель**

1. Применяется, когда знание перенесено, а прежнее место остаётся ожидаемым для читателя.
2. Документ-указатель НЕ ДОПУСКАЕТСЯ содержащим знание — только назначение и цель перенаправления.
3. Цепочки указателей НЕ ДОПУСКАЮТСЯ: указатель ведёт непосредственно к владельцу.

**R5 · Реестровая**

1. Ссылка выполняется по идентификатору, а не по названию: название меняется, идентификатор — нет.
2. Каждый идентификатор ОБЯЗАН существовать в реестре.
3. Реестр ОБЯЗАН содержать ровно одну запись на идентификатор.

**R6 · Навигационная**

1. НЕ ДОПУСКАЕТСЯ переносить знание: удаление такой ссылки не должно менять смысл текста.
2. Не участвует в каскаде.

**R7 · Внешняя**

1. ОБЯЗАНА проходить через реестр внешних источников, а не размещаться в тексте напрямую.
2. ОБЯЗАНА содержать дату обращения.
3. Внешний источник НЕ ДОПУСКАЕТСЯ как единственное основание нормативного утверждения: внешние ресурсы исчезают и меняются.
4. При необходимости постоянства делается локальная копия с указанием условий использования.

### 6.3. Чек-лист CR1–CR14

| # | Проверка | Авто |
|---|----------|------|
| CR1 | Каждая ссылка разрешается: цель существует | да |
| CR2 | Каждая ссылка имеет определимый тип | да |
| CR3 | Симметрия зависимости и каскада соблюдена с обеих сторон | да |
| CR4 | Граф зависимостей ацикличен | да |
| CR5 | Ни одна зависимость не направлена в нижестоящий слой | да |
| CR6 | Ни одна зависимость не нарушает порядок чтения | да |
| CR7 | Ссылка на раздел указывает на существующий якорь | да |
| CR8 | Каждая цитата содержит атрибуцию и не превышает порог объёма | частично |
| CR9 | Каждая цитата нормативного утверждения фиксирует версию источника | да |
| CR10 | Нет цепочек указателей длиннее одного шага | да |
| CR11 | Нет входящих ссылок на документы в состоянии `Superseded` | да |
| CR12 | Нет осиротевших документов: на каждый документ есть хотя бы одна входящая ссылка | да |
| CR13 | Каждая внешняя ссылка зарегистрирована и содержит дату обращения | да |
| CR14 | Число зависимостей документа не превышает порог привязки | да |

### 6.4. Ссылки на разделы

1. Ссылка на часть документа ОБЯЗАНА указывать на устойчивый якорь: номер раздела или явный идентификатор, но не на заголовок в свободной форме.
2. Нумерация разделов в документе ОБЯЗАНА быть устойчивой: перенумерация существующих разделов — изменение, ломающее входящие ссылки, и выполняется как миграция (DES-015).
3. Ссылка на раздел документа в состоянии ниже `Approved` НЕ ДОПУСКАЕТСЯ из документа в состоянии `Approved` или `Canonical`.

### 6.5. Перенаправление входящих ссылок

При замене, разделении или слиянии документов действует правило: **исходящие ссылки принадлежат автору, входящие — корпусу**.

1. Автор изменения ОБЯЗАН найти все входящие ссылки на изменяемый документ.
2. Каждая входящая ссылка ОБЯЗАНА быть перенаправлена **в том же изменении**.
3. Перевод документа в `Superseded` НЕ ДОПУСКАЕТСЯ до завершения перенаправления.
4. Оставление ссылки на `Superseded` документ «до лучших времён» НЕ ДОПУСКАЕТСЯ: читатель, идущий по ней, получает недействительное знание без предупреждения.

### 6.6. Осиротевшие документы

Документ, на который нет ни одной входящей ссылки, недостижим при чтении и не участвует ни в одном каскаде.

Обработка:

| Причина | Действие |
|---------|----------|
| Забыли сослаться | добавить ссылку из логичного места |
| Документ не нужен | перевести в `Superseded` |
| Документ — корень слоя | добавить в реестр порядка чтения; реестр считается входящей ссылкой |

Осиротевший документ — не безобидная мелочь: он продолжает проходить проверки формы и выглядеть действующим, оставаясь при этом вне каскада изменений.

### 6.7. Плотность ссылок

1. Каждое нормативное утверждение, опирающееся на другой документ, ОБЯЗАНО содержать ссылку на него.
2. Ссылка на один и тот же документ СЛЕДУЕТ ставиться один раз на раздел, а не при каждом упоминании.
3. Избыточная плотность ссылок затрудняет чтение и не улучшает проверок: граф строится по метаданным, а не по числу вхождений в тексте.
