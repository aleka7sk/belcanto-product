# Соответствие стандарту и привязка

> Стандарт оперирует абстракциями: «вышестоящий документ», «владеющая роль», «порог», «порядок авторитета». Пока эти абстракции не получат значений, ни одно требование не проверяемо.
>
> Привязка — набор документов конкретного репозитория, дающий эти значения. Без неё стандарт — текст, а не инструмент.

---

## 1. Purpose · Назначение

Определить, что репозиторий обязан предоставить, чтобы стандарт стал применимым, и как заявляется и проверяется соответствие.

## 5. Validation Rules · Правила валидации

1. Каждое требование B1–B12 проверяемо наличием или отсутствием документа привязки.

## 6. Content · Содержание

### 6.1. Что даёт привязка

```
DES                          Привязка                     Результат
──────────────────────────────────────────────────────────────────
«вышестоящий документ»   →   модель слоёв             →   проверяемое направление
«порядок авторитета»     →   полный порядок           →   разрешимый конфликт
«владеющая роль»         →   каталог ролей            →   адресуемая ответственность
«порог»                  →   числовые значения        →   срабатывающая проверка
«обязательные поля»      →   состав метаданных        →   автоматическая валидация
«реестр»                 →   конкретные документы     →   вычислимый корпус
```

### 6.2. Требования к привязке

| # | Требование | Без него не работает |
|---|------------|----------------------|
| **B1** | **Модель слоёв или зон**: перечень, вопрос каждой зоны, направление зависимостей | DES-002 (E4), DES-005 (CR5) |
| **B2** | **Полный порядок авторитета**: для любой пары документов и любого предмета — однозначный результат либо явное «требуется решение» | DES-009 |
| **B3** | **Каталог ролей**: перечень, зоны ответственности, распорядитель по умолчанию | DES-007 |
| **B4** | **Состав метаданных документа**: обязательные поля, покрывающие владение понятиями, исключения, зависимости, каскад, состояние, версию | DES-004 (V1) |
| **B5** | **Схемы идентификаторов**: для документов, понятий, решений, миграций | DES-005 (R5), DES-014 |
| **B6** | **Реестр владения понятиями** | DES-002 (E2), DES-009 (A1, A2) |
| **B7** | **Реестр порядка чтения** | DES-004 (V4.1) |
| **B8** | **Реестр терминов** с указанием владельца каждого термина | DES-014 |
| **B9** | **Реестр решений**: механизм фиксации выбора | DES-006 (класс B), DES-009 |
| **B10** | **Реестр миграций** | DES-015 (6.9) |
| **B11** | **Числовые пороги**: сроки состояний, интервалы ревизии, предельные значения бюджета, объём цитаты, число узлов диаграммы | DES-001, DES-005, DES-010, DES-012 |
| **B12** | **Инструментарий проверки**: реализация автоматизируемых пунктов DES-004 и детекторов DES-009 | уровень соответствия 1 |

Отсутствие любого требования делает соответствующие проверки невыполнимыми. Заявление соответствия при неполной привязке недействительно.

### 6.3. Заявление соответствия

Репозиторий, применяющий стандарт, ОБЯЗАН содержать заявление:

```
Версия стандарта:      <версия DES>
Уровень соответствия:  1 | 2 | 3
Документы привязки:    <перечень с указанием, какое требование B1–B12 закрывает каждый>
Дата проверки:         <дата>
Отклонения:            <ссылка на реестр отклонений>
Непокрытые требования: <перечень или «нет»>
```

1. Заявление ОБЯЗАНО быть проверено, а не объявлено. Непроверенный уровень недействителен.
2. Заявление ОБЯЗАНО обновляться при повышении `MAJOR` стандарта.
3. Строка непокрытых требований ОБЯЗАТЕЛЬНА и не может отсутствовать по умолчанию.

### 6.4. Уровни соответствия

| Уровень | Условия |
|---------|---------|
| **1 · Форма** | B1, B3, B4, B5, B7, B11, B12 предоставлены; DES-001…005 соблюдаются; автоматизируемые пункты V1 и V2 автоматизированы; проверка выполняется до приёма изменения |
| **2 · Прослеживаемость** | уровень 1 + B2, B6, B9; DES-006, 007, 009 соблюдаются; граф зависимостей полон и симметричен; покрытие вывода не ниже порога; детекторы A1, A5–A9, A13 работают |
| **3 · Каноничность** | уровень 2 + B8, B10; DES-008, 010–015 соблюдаются; покрытие вывода 100 %; свежесть каскада 100 %; гипотез в канонических документах нет; конфликтов сверх срока нет; изменения агента проходят по протоколу |

Уровень заявляется целиком. Частичное соответствие уровню не засчитывается: пропущенное требование обычно и есть то, которое перестало соблюдаться первым.

### 6.5. Ужесточение и ослабление

1. Привязка ДОПУСКАЕТСЯ **ужесточать** требования стандарта: сокращать сроки, снижать пороги, добавлять обязательные поля и проверки.
2. Привязка НЕ ДОПУСКАЕТСЯ **ослаблять** требования: продлевать предельные сроки сверх стандарта, отменять обязательные проверки, разрешать запрещённое.
3. Привязка ДОПУСКАЕТСЯ добавлять собственные правила, не противоречащие стандарту.
4. При противоречии привязки и стандарта действует стандарт. Привязка подлежит исправлению.
5. Требуемое ослабление оформляется отклонением (6.6), а не изменением привязки.

### 6.6. Реестр отклонений

Отклонение — зафиксированное несоблюдение требования стандарта, признаваемое временно допустимым.

Каждое отклонение ОБЯЗАНО содержать:

```
Идентификатор:     <идентификатор отклонения>
Требование:        <пункт стандарта>
Область:           <документы или проверки, которых касается>
Обоснование:       <почему соблюдение сейчас невозможно>
Компенсация:       <чем снижается риск>
Срок:              <дата пересмотра>
Ответственный:     <роль>
```

Правила:

1. Отклонение без срока НЕ ДОПУСКАЕТСЯ.
2. Отклонение от требования модальности «ОБЯЗАН» понижает заявленный уровень соответствия до тех пор, пока действует.
3. Просроченное отклонение подлежит либо закрытию, либо пересмотру с новым обоснованием.
4. Отсутствие реестра отклонений при фактических отклонениях означает недостоверность заявления соответствия.

Реестр существует не ради формальности: отклонение, зафиксированное с обоснованием и сроком, управляемо; отклонение, принятое молча, неотличимо от неисправности.

### 6.7. Порядок внедрения

Внедрение в существующий репозиторий выполняется как последовательность миграций (DES-015).

| Фаза | Содержание | Класс миграции |
|------|------------|----------------|
| 1 | Создать привязку: B1, B3, B4, B5, B7, B11 | M-A, M-B |
| 2 | Привести метаданные существующих документов к новому составу | M-A |
| 3 | Построить реестры: B6, B8, B9, B10 | M-A |
| 4 | Автоматизировать проверки: B12; заявить уровень 1 | M-E |
| 5 | Достроить прослеживаемость и каскадные отметки; заявить уровень 2 | M-F |
| 6 | Ввести протокол агента, бюджеты, правила диаграмм, примеров, терминов; заявить уровень 3 | M-E |

**Правила внедрения.**

1. Фазы НЕ ДОПУСКАЮТСЯ к перестановке: каждая опирается на предыдущую.
2. Новые документы с фазы 1 создаются сразу по стандарту.
3. Существующие документы приводятся к стандарту по мере изменения; массовая переработка НЕ ТРЕБУЕТСЯ и СЛЕДУЕТ её избегать.
4. Каждая фаза имеет окно совместимости, в течение которого допустимы обе формы.
5. Смешанное состояние в течение внедрения легально при наличии открытой миграции.

### 6.8. Извлечение стандарта

Стандарт переносится в другой репозиторий копированием каталога `meta/standard/` целиком.

1. Документы стандарта НЕ ДОПУСКАЮТСЯ ссылающимися за пределы каталога стандарта.
2. Документы стандарта НЕ ДОПУСКАЮТСЯ содержащими имена, специфичные для предметной области.
3. Привязка создаётся заново для каждого репозитория: она не переносится.
4. Версия стандарта переносится без изменений. Локальные правки стандарта НЕ ДОПУСКАЮТСЯ: местные требования выражаются ужесточением в привязке (6.5).

### 6.9. Привязка в настоящем репозитории

> Раздел является единственным местом стандарта, указывающим на конкретный репозиторий, и не переносится при извлечении (6.8).

Требования B1–B12 закрываются документами каталога `meta/` вне `meta/standard/`. Соответствие требований и документов привязки, заявленный уровень, реестр отклонений и непокрытые требования ведутся в документе привязки, объявляющем соответствие.
