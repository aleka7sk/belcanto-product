# Бюджет ответственности документа

> Документ разрушается не от длины, а от количества вопросов, на которые он отвечает. Длинный реестр здоров. Короткий документ, отвечающий на три вопроса, — нет.
>
> Бюджет ответственности заменяет интуицию «пора делить» измеримыми величинами.

---

## 1. Purpose · Назначение

Задать предел ответственности одного документа так, чтобы перегрузку можно было обнаружить измерением, а не заметить постфактум по трудности сопровождения.

## 6. Content · Содержание

### 6.1. Максимальная ответственность документа

Документ ОБЯЗАН удовлетворять всем ограничениям одновременно:

| # | Ограничение | Величина |
|---|-------------|----------|
| B1 | Вопросов, на которые отвечает | ровно **1** |
| B2 | Ответственных владельцев | ровно **1** |
| B3 | Классов читателей, для которых обязателен | **1**, СЛЕДУЕТ; более — признак смешения аудиторий |
| B4 | Понятий во владении | ≤ порога привязки; СЛЕДУЕТ ≤ 7 |
| B5 | Правил валидации документа | 3–8 |
| B6 | Уровней вложенности разделов | ≤ 3 |
| B7 | Зависимостей | ≤ порога привязки |

B1 и B2 — абсолютные. Остальные — пороговые: превышение не запрещает существование документа, а требует обоснования либо разделения.

### 6.2. Тест единственного вопроса

Основной инструмент. Выполняется на любой стадии жизни документа.

```
1. Сформулировать вопрос документа одним предложением.
2. Проверить формулировку:
   — содержит «и», «а также», «включая»?        → два вопроса
   — описывает тему, а не вопрос?               → границы не заданы
   — требует более одного предложения?          → вопрос не единственный
3. Проверить каждый раздел содержания:
   — отвечает ли раздел на заявленный вопрос?
   — раздел, не отвечающий на него, принадлежит другому документу.
```

Тест выполняется **по разделам**, а не по документу целиком. Перегрузка всегда локальна: она начинается с одного раздела, который «логично было добавить сюда же».

### 6.3. Измерения

| # | Измерение | Как считается | Сигнал |
|---|-----------|---------------|--------|
| M1 | Число понятий во владении | по заявке документа | > порога |
| M2 | Число вопросов | тест 6.2, вручную | > 1 |
| M3 | Число ролей-владельцев разделов | опрос владельца: кто отвечает за каждый раздел | > 1 |
| M4 | Число различных источников | таблица вывода | резкий рост при неизменной зоне |
| M5 | Расслоение по частоте изменений | история изменений по разделам | часть разделов меняется многократно чаще остальных |
| M6 | Совместная изменяемость | доля изменений, затрагивающих более одного раздела | низкая доля = разделы независимы |
| M7 | Число зависимостей | метаданные | > порога |
| M8 | Число входящих ссылок на разные разделы | граф ссылок | разные потребители ссылаются на непересекающиеся части |

**M5 и M6 — сильнейшие признаки.** Если части документа никогда не меняются вместе, они не связаны ничем, кроме соседства в файле.

### 6.4. Признаки перегрузки

| # | Признак | Что означает |
|---|---------|--------------|
| P1 | В формулировке назначения есть «и» | два вопроса |
| P2 | Двое настаивают на владении разными частями | две зоны ответственности |
| P3 | Читатели читают только «свою» часть | несколько аудиторий |
| P4 | Разделы никогда не меняются вместе (M6) | отсутствие связности |
| P5 | Оглавление глубже трёх уровней | иерархия подменяет декомпозицию |
| P6 | Правил валидации больше восьми | документ отвечает за слишком многое |
| P7 | Список исключений длиннее списка владения | документ определён через отрицание |
| P8 | Разные разделы выводятся из разных слоёв | смешение уровней |
| P9 | Изменение одного раздела регулярно требует правки другого | скрытая связь, требующая явного выражения |

Один признак — повод для наблюдения. Два и более — основание для разделения (DES-011).

### 6.5. Объём текста

Объём — **вторичный** признак и самостоятельным критерием не является.

1. Объём НЕ ДОПУСКАЕТСЯ как единственное основание для разделения.
2. Привязка ДОПУСКАЕТСЯ задавать ориентировочные пороги объёма как повод для проверки бюджета, но не как повод для разделения.
3. Превышение порога объёма при выполнении B1–B7 нарушением не является.

Разделение по объёму даёт худший из возможных результатов: два документа, каждый из которых отвечает на половину вопроса, и ни один — на целый.

### 6.6. Исключение для реестров

**Реестр** — документ, содержание которого является перечнем однородных записей с идентификаторами.

Для реестров:

1. B4 (число понятий) НЕ ПРИМЕНЯЕТСЯ: реестр владеет одним понятием — самим перечнем. Записи не являются понятиями реестра.
2. Ограничение объёма НЕ ПРИМЕНЯЕТСЯ: рост реестра — нормальное следствие роста корпуса.
3. B1, B2, B5, B6 ПРИМЕНЯЮТСЯ полностью.
4. Реестр НЕ ДОПУСКАЕТСЯ содержащим развёрнутое описание записей: описание принадлежит отдельным документам, реестр хранит идентификаторы и связи.

Нарушение п. 4 — типичный способ превратить здоровый реестр в перегруженный документ.

### 6.7. Что не считается перегрузкой

| Ситуация | Почему |
|----------|--------|
| Длинный реестр | см. 6.6 |
| Много примеров к одному правилу | признак неясности правила (DES-013), не перегрузки |
| Много разделов при одном вопросе | структура ответа, а не расширение зоны |
| Много входящих ссылок на один раздел | признак полезности |
| Много зависимостей у обзорного документа | обзор по своей природе сводит источники |

### 6.8. Когда бюджет проверяется

| Момент | Что проверяется |
|--------|-----------------|
| Создание (DES-002) | B1–B7 по заявке |
| Переход в `Review` | B1–B7 по фактическому содержанию |
| Переход в `Canonical` | B1–B7 + измерения M1, M4, M7 |
| Плановая ревизия | все измерения, включая M5, M6 |
| После трёх изменений `MINOR` подряд | M1, M4 — рост зоны без явного решения |

Последняя строка существенна: зона документа расширяется не решением, а серией мелких дополнений, каждое из которых по отдельности выглядит уместным.
