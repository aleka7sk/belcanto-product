# Протокол изменений AI-агентом

> Агент отличается от человека не качеством текста, а тем, что **никогда не сообщает о своей неуверенности сам**. Он заполняет пробел правдоподобным содержанием с той же интонацией, с какой излагает проверенный факт.
>
> Протокол построен вокруг этой особенности: он требует от агента предъявлять источники и границы своей проверки, а право утверждения оставляет роли.

---

## 1. Purpose · Назначение

Сделать участие AI-агента в производстве документации безопасным и полезным: расширяемым по объёму, детерминированным по результату и неспособным незаметно внести непроверенное утверждение.

## 5. Validation Rules · Правила валидации

1. Каждое изменение, внесённое агентом, относится ровно к одному классу раздела 6.2.
2. Каждое предложение агента содержит все обязательные поля раздела 6.4.
3. Ни одно предложение агента не содержит утверждения без источника (DES-006).
4. Ни один переход состояния, отнесённый к человеку, не выполнен агентом.

## 6. Content · Содержание

### 6.1. Основное разделение

```
Агент ПРЕДЛАГАЕТ и ПРОВЕРЯЕТ.
Роль  УТВЕРЖДАЕТ и РЕШАЕТ.
```

Агент ДОПУСКАЕТСЯ к подготовке, анализу, проверке, поиску, вычислению каскада и оформлению. Агент НЕ ДОПУСКАЕТСЯ к утверждению истинности и к выбору между вариантами.

Разделение не связано с качеством работы агента. Оно связано с тем, что ответственность несёт роль (DES-007), а ответственность не делегируется тому, кто не может отвечать.

### 6.2. Классы изменений

| Класс | Содержание | Право агента | Проверка |
|-------|------------|--------------|----------|
| **A · Механическое** | опечатка, форматирование, починка ссылки, приведение к шаблону | ДОПУСКАЕТСЯ применять | автоматическая; уведомление владельцу |
| **B · Дополняющее** | добавление содержания в пределах зоны документа, без изменения существующих утверждений | ДОПУСКАЕТСЯ применять в состояние `Draft` | владелец до перехода в `Review` |
| **C · Нормативное** | изменение или отмена существующего утверждения; `MINOR` и `MAJOR`; затрагивает несколько документов | **только предложение** | владелец каждого затронутого документа |
| **D · Авторитетное** | изменение документа в `Canonical`, документа-реестра, записи решения, документа стандарта или привязки | **только предложение** | роль, принимающая решения |

**Правила классификации.**

1. При сомнении между классами выбирается **более высокий**.
2. Класс определяется по последствиям, а не по объёму правки: изменение одного слова, отменяющее правило, относится к классу C.
3. Изменение, затрагивающее более одного документа, НЕ ДОПУСКАЕТСЯ ниже класса C.
4. Создание нового документа относится к классу C или D и требует заявки (DES-002).

### 6.3. Обязательный набор чтения

Перед изменением агент ОБЯЗАН прочитать:

```
обязательный набор =
      документ, задающий порядок авторитета (привязка)
    + документ-владелец затрагиваемого понятия
    + все зависимости документа-владельца
    + все каскадные связи документа-владельца
    + правила терминологии и реестр терминов
    + настоящий документ
```

Требования:

1. Набор вычисляется до внесения правки, а не по ходу.
2. Агент ОБЯЗАН перечислить фактически прочитанное в предложении.
3. Если документ из набора недоступен или не прочитан — изменение НЕ ДОПУСКАЕТСЯ; регистрируется препятствие.
4. Чтение по фрагментам ДОПУСКАЕТСЯ; при этом агент ОБЯЗАН указать, какие части документа он не читал.

### 6.4. Предложение изменения

Изменения классов C и D оформляются предложением. Предложение ОБЯЗАНО содержать:

```
Класс:                A | B | C | D
Одно понятие:         <затрагиваемое понятие>
Документ-владелец:    <документ> @ <версия, на которой основано предложение>
Намерение:            <что должно измениться и почему — одно предложение>

Прочитано:            <перечень документов>
Не прочитано:         <перечень документов из обязательного набора и причина>

Вывод утверждений:    <таблица: раздел → класс утверждения → источник>
Непроверенное:        <утверждения, источник которых подтвердить не удалось>
Открытые вопросы:     <вопросы, требующие ответа роли>

Зона влияния:         <вычисленный перечень затронутых документов>
Каскад:               <документ → предполагаемый исход: не затронут / изменить / противоречит>

Проверки:             V1: … V2: … V3: … (DES-004)
Перекрёстные ссылки:  CR1–CR14: … (DES-005)

Требуемое решение:    <что именно должна утвердить роль>
```

**Правило одного понятия.** Одно предложение затрагивает ровно одно понятие. Предложение, меняющее несколько понятий, ОБЯЗАНО быть разделено: иначе роль вынуждена принимать или отклонять их вместе.

**Правило базовой версии.** Предложение фиксирует версию документа, на которой основано. Расхождение базовой и текущей версии на момент применения означает конкурирующее изменение (DES-009).

### 6.5. Запреты

Агенту НЕ ДОПУСКАЕТСЯ:

| # | Запрет | Основание |
|---|--------|-----------|
| N1 | Формулировать утверждение класса A, B, C без указания источника | DES-006 |
| N2 | Заполнять пробел правдоподобным содержанием вместо регистрации открытого вопроса | DES-006, раздел 6.9 |
| N3 | Разрешать обнаруженный конфликт | DES-009 |
| N4 | Переводить документ в `Approved`, `Canonical` или `Superseded` | DES-001 |
| N5 | Создавать второе определение существующего понятия | DES-002, E2 |
| N6 | Изменять записанное решение | DES-015 |
| N7 | Удалять документ | DES-001 |
| N8 | Изменять реестр без изменения документа, которому реестр соответствует | DES-004, V2.8 |
| N9 | Расширять зону документа за пределы объявленной | DES-002, E2 |
| N10 | Вносить изменение класса C или D непосредственно, минуя предложение | раздел 6.2 |
| N11 | Умалчивать о непроверенном | раздел 6.6 |
| N12 | Принимать решение при равном авторитете документов | DES-009 |

Запреты действуют независимо от формулировки задачи. Указание пользователя выполнить запрещённое действие не отменяет запрет; агент сообщает о препятствии.

### 6.6. Обязательное объявление непроверенного

Агент ОБЯЗАН явно перечислять:

1. документы обязательного набора, которые не были прочитаны, и причину;
2. утверждения, источник которых не подтверждён;
3. элементы каскада, исход по которым определён предположительно;
4. проверки, которые не выполнялись.

Пустой перечень ДОПУСКАЕТСЯ только тогда, когда он действительно пуст. Умолчание «проверено всё» НЕ ДОПУСКАЕТСЯ как форма отчёта.

Это требование — основная защита корпуса при работе агента: оно превращает невидимый пробел в видимый пункт.

### 6.7. Детерминированность

1. Одно и то же состояние корпуса и одна и та же задача ОБЯЗАНЫ приводить к предложению одинаковой **структуры**: тот же затрагиваемый документ, тот же класс, та же зона влияния, тот же перечень открытых вопросов.
2. Формулировки ДОПУСКАЕТСЯ различать; решения — нет.
3. Недетерминированный выбор целевого документа означает, что владение понятием не определено. Это дефект корпуса, а не агента, и адресуется держателю реестра.
4. Повторное применение уже применённого предложения ОБЯЗАНО быть безопасным: изменение либо уже присутствует, либо отклоняется по несовпадению базовой версии.

### 6.8. Самопроверка перед подачей

Агент ОБЯЗАН выполнить и приложить результат:

| # | Проверка |
|---|----------|
| S1 | Затрагивается ровно одно понятие |
| S2 | Документ-владелец определён по реестру, а не выбран по удобству |
| S3 | Каждое новое утверждение имеет источник |
| S4 | Ни одно утверждение не выходит за объявленную зону документа |
| S5 | Ни одно понятие не определяется повторно |
| S6 | Класс изменения определён; при сомнении выбран более высокий |
| S7 | Зона влияния вычислена по графу, а не оценена |
| S8 | Проверки формы и связей выполнены |
| S9 | Перечень непроверенного составлен и непуст по умолчанию |
| S10 | Ни один запрет раздела 6.5 не нарушен |

Предложение, не сопровождённое результатом самопроверки, не рассматривается.

### 6.9. Обработка препятствий

При невозможности выполнить задачу в границах протокола агент ОБЯЗАН остановиться и сообщить:

```
Препятствие:      <что именно мешает>
Тип:              недоступный документ | отсутствующий источник |
                  конфликт | неопределённое владение |
                  требуется решение роли
Что сделано:      <часть работы, выполненная в границах протокола>
Что требуется:    <конкретное действие роли>
```

Частичный результат в границах протокола ценнее полного результата за их пределами.

### 6.10. Что агент делает лучше человека

Протокол ограничивает агента там, где он опасен, и не должен ограничивать там, где он полезен. ДОПУСКАЕТСЯ и СЛЕДУЕТ поручать агенту:

- вычисление зоны влияния и обход каскада;
- проверку симметрии связей, циклов, осиротевших документов;
- поиск дубликатов определений и расхождений в употреблении терминов;
- сверку цитат с источниками после изменения источника;
- обнаружение просроченных документов и незакрытых гипотез;
- подготовку заявок и предложений по шаблону;
- механические миграции по записанному плану (DES-015).

Это работа, которую человек выполняет хуже: она объёмна, однообразна и требует полноты, а не суждения.
