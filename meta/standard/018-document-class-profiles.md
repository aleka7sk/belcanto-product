# Профили классов документов

> Конвейер один. Но документ о замысле и документ о модели ломаются в разных местах: первый — на утверждениях, выдающих желание за решение, второй — на утверждениях, выдающих структуру за определение.
>
> Профиль класса не меняет стадии. Он указывает, **где именно** для данного класса сосредоточен риск и что рецензент обязан проверить прежде всего.

---

## 1. Purpose · Назначение

Обеспечить одинаковую применимость конвейера ко всем видам документов, не сводя их к общему знаменателю: показать, чем производство каждого класса отличается при неизменной последовательности стадий.

## 5. Validation Rules · Правила валидации

1. Каждый класс раздела 6.2 имеет определённый вопрос, преобладающий класс утверждений и режим отказа.
2. Ни один профиль не добавляет и не удаляет стадий конвейера.
3. Правило выбора класса (6.3) даёт однозначный результат для любого документа.
4. Ни один профиль не содержит названий, специфичных для предметной области.

## 6. Content · Содержание

### 6.1. Что задаёт профиль и что не задаёт

| Профиль задаёт | Профиль не задаёт |
|----------------|-------------------|
| Преобладающий класс утверждений | Перечень стадий |
| Допустимые типы источников | Порядок стадий |
| Стадию наибольшего риска | Типы ворот |
| Классовые режимы отказа | Стратегии восстановления |
| Дополнительные критерии рецензии | Условия выхода X1–X12 |
| Требуемую компетенцию рецензента | Роли конкретного репозитория |

Профиль **ужесточает**, но не ослабляет: он добавляет критерии рецензии, не отменяя общих.

### 6.2. Классы документов

| Класс | Вопрос класса | Преобладающие утверждения | Стадия риска |
|-------|---------------|---------------------------|--------------|
| **C1 · Замысел** | Зачем это существует и чем не является? | B решённое | P3 |
| **C2 · Наблюдение** | Как это происходит сегодня? | C наблюдённое | P2 |
| **C3 · Определение** | Что означает это слово? | D определяющее | P1 |
| **C4 · Модель** | Как устроен предмет? | A + D | P3 |
| **C5 · Опыт** | Как человек с этим встречается? | A выведенное | P2 |
| **C6 · Поведение** | Что это делает? | A выведенное | P3 |
| **C7 · Форма** | Как это выглядит, звучит, движется? | A + D | P3 |
| **C8 · План** | В каком порядке и объёме? | B решённое | P2 |
| **C9 · Реестр** | Что вообще существует? | записи, а не утверждения | P4 |

#### C1 · Замысел

| | |
|---|---|
| **Источники** | записанные решения; внешний контекст; документы наблюдения |
| **Не источники** | нижестоящие слои; предпочтения автора; аналоги без записанного решения об их применимости |
| **Стадия риска** | **P3** — намерение легко подменяется намерением звучать хорошо |
| **Главный режим отказа** | **Желание вместо решения.** Утверждение выглядит нормативным, но не выведено ни из какого решения и потому ничего не запрещает |
| **Проверка на воротах P3** | Каждое утверждение отвечает на вопрос: «что конкретно оно запрещает?» Утверждение, не запрещающее ничего, отклоняется как пояснительное |
| **Дополнительные критерии рецензии** | Утверждения проверяемы: по каждому можно отклонить конкретное решение. Присутствуют утверждения об исключённом, а не только о желаемом |
| **Компетенция рецензента** | Роль, принимающая решения |
| **Особенность** | Класс с наибольшим весом: из него выводятся C4–C8. Ошибка здесь распространяется по всему корпусу |

---

#### C2 · Наблюдение

| | |
|---|---|
| **Источники** | непосредственное наблюдение; свидетельство носителя процесса; существующие записи |
| **Не источники** | предположение о том, как «обычно бывает»; целевое состояние |
| **Стадия риска** | **P2** — источником незаметно становится память автора |
| **Главный режим отказа** | **Правдоподобная реконструкция.** Автор описывает, как процесс устроен по всей видимости, не отличая это от того, что подтверждено |
| **Проверка на воротах P2** | Каждое утверждение имеет носителя источника и дату подтверждения. Неподтверждённое помечено гипотезой и зарегистрировано |
| **Дополнительные критерии рецензии** | Ни одно утверждение не описывает будущее. Подтверждённое отделено от предполагаемого явно, а не интонацией |
| **Компетенция рецензента** | Носитель наблюдаемого процесса |
| **Особенность** | Единственный класс, где допустим утвердительный ответ на E0 без отказа: наблюдение может дублировать наблюдение, если получено независимо. Дублирование фиксируется как подтверждение |

---

#### C3 · Определение

| | |
|---|---|
| **Источники** | документы замысла; наблюдение; необходимость, выраженная документами-потребителями |
| **Не источники** | реализация; другой словарь без решения о его принятии |
| **Стадия риска** | **P1** — понятие часто уже принадлежит другому документу |
| **Главный режим отказа** | **Второе определение.** Определение вводится там, где нужно было сослаться |
| **Проверка на воротах P1** | Ни одно заявляемое понятие не занято. Каждое удовлетворяет критерию признания термином (DES-014, раздел 6.1) |
| **Дополнительные критерии рецензии** | Форма F1–F7 соблюдена. Определение не содержит правил применения. Определение не опирается на неопределённые термины |
| **Компетенция рецензента** | Носитель предметного смысла |
| **Особенность** | Утверждения класса D не имеют внешнего источника: документ **сам** является источником. Поэтому ворота P1 здесь несут нагрузку, которую в других классах несут ворота P3 |

#### C4 · Модель

| | |
|---|---|
| **Источники** | определения; замысел; наблюдение |
| **Не источники** | опыт, поведение, форма — они выводятся из модели, а не наоборот |
| **Стадия риска** | **P3** — структурные утверждения маскируются под определения |
| **Главный режим отказа** | **Смешение смысла и структуры.** Документ определяет слово там, где обязан описать устройство, — и становится вторым словарём |
| **Проверка на воротах P3** | Каждое утверждение класса D проверяется на принадлежность: определяет ли оно **слово** или **структуру**. Определение слова принадлежит классу C3 |
| **Дополнительные критерии рецензии** | Каждое имя модели присутствует в реестре терминов. Модель не содержит утверждений об интерфейсе и представлении. Правила расчёта отделены от структуры |
| **Компетенция рецензента** | Носитель предметного смысла и роль, отвечающая за модель — **обе** |
| **Особенность** | Наиболее плотный по связям класс. Зона влияния изменения обычно широка, поэтому стадия P8 здесь дороже, чем в других классах, и сокращению не подлежит |

---

#### C5 · Опыт

| | |
|---|---|
| **Источники** | замысел; описания ролей; модель; наблюдение |
| **Не источники** | воображение автора; поведение отдельных возможностей; форма |
| **Стадия риска** | **P2** — опыт легко «выводится» из ничего, поскольку кажется очевидным |
| **Главный режим отказа** | **Вывод из ниоткуда.** Сценарий выглядит убедительно и не опирается ни на замысел, ни на модель, ни на наблюдение |
| **Проверка на воротах P2** | Для каждого шага сценария существует источник: роль из описания ролей, элемент модели, наблюдение |
| **Дополнительные критерии рецензии** | Каждый шаг связан с элементом модели. Каждый шаг несёт ценность для роли. Сценарий описывает целевое состояние, а не текущее — и это объявлено |
| **Компетенция рецензента** | Роль, отвечающая за замысел, и носитель наблюдаемого процесса |
| **Особенность** | Единственный класс, где рецензент обязан проверить **полноту пути**, а не только истинность шагов: сценарий с верными шагами и разрывом между ними бесполезен |

---

#### C6 · Поведение

| | |
|---|---|
| **Источники** | опыт; модель; замысел; план |
| **Не источники** | форма; реализация |
| **Стадия риска** | **P3** — утверждения о поведении подменяют утверждения о модели |
| **Главный режим отказа** | **Присвоение правила.** Документ формулирует правило расчёта или условие, владельцем которого является модель, и оно начинает существовать в двух местах |
| **Проверка на воротах P3** | Каждое утверждение проверяется: описывает ли оно **что происходит** (поведение) или **по каким правилам** (модель). Второе выносится ссылкой |
| **Дополнительные критерии рецензии** | Каждое действие соответствует элементу модели. Определены все состояния, включая отсутствие данных и отказ. Правила расчёта не изложены, а указаны ссылкой |
| **Компетенция рецензента** | Роль, отвечающая за замысел; при затрагивании модели — также роль модели |
| **Особенность** | Самый многочисленный класс. Именно здесь дублирование накапливается быстрее всего, поскольку каждый документ соблазняет изложить «для полноты» правило из модели |

---

#### C7 · Форма

| | |
|---|---|
| **Источники** | замысел; опыт; требования доступности |
| **Не источники** | вкус; аналоги без решения об их применимости; реализация |
| **Стадия риска** | **P3** — значения подменяют смыслы |
| **Главный режим отказа** | **Значение вместо роли.** Документ фиксирует конкретную величину там, где обязан определить смысл, — и величина немедленно расходится с реестром значений |
| **Проверка на воротах P3** | Каждое утверждение проверяется: определяет ли оно **смысл** или **величину**. Величина принадлежит одному документу-владельцу значений |
| **Дополнительные критерии рецензии** | Ни одна величина не изложена вне владельца значений. Ни один смысл не передан исключительно цветом или начертанием. Требования доступности выполнены как условие приёмки, а не как пожелание |
| **Компетенция рецензента** | Роль, отвечающая за форму; при затрагивании доступности — независимая проверка |
| **Особенность** | Класс с наибольшим соблазном к диаграммам. Правило ненормативности диаграмм (DES-012) здесь нарушается чаще всего и проверяется на P5 отдельно |

---

#### C8 · План

| | |
|---|---|
| **Источники** | замысел; реестры существующего; зависимости между записями реестров |
| **Не источники** | оптимизм; поведение отдельных возможностей |
| **Стадия риска** | **P2** — план выводится из неполного перечня существующего |
| **Главный режим отказа** | **Быстрое устаревание.** План верен в момент принятия и перестаёт быть верным раньше, чем кто-либо это заметит |
| **Проверка на воротах P2** | Реестры, из которых выводится план, полны и находятся в состоянии не ниже `Approved` |
| **Дополнительные критерии рецензии** | Порядок не нарушает зависимостей. Каждая единица плана существует в реестре. Исключённое перечислено с причиной наравне с включённым |
| **Компетенция рецензента** | Роль, принимающая решения |
| **Особенность** | Самый короткий интервал ревизии из всех классов. Профиль ОБЯЗЫВАЕТ привязку задать для него наименьший интервал |

---

#### C9 · Реестр

| | |
|---|---|
| **Источники** | документы, описывающие записи реестра |
| **Не источники** | сами записи — реестр их перечисляет, но не определяет |
| **Стадия риска** | **P4** — реестр разрастается описаниями |
| **Главный режим отказа** | **Поглощение описаний.** В реестр переносится содержание описываемых документов «для удобства», и он становится вторым источником |
| **Проверка на воротах P4** | Каждый столбец реестра — идентификатор, состояние или связь. Столбец с описанием отклоняется |
| **Дополнительные критерии рецензии** | Каждая запись имеет идентификатор. Каждая запись имеет документ-описание либо является самодостаточной по природе. Реестр не содержит развёрнутых описаний |
| **Компетенция рецензента** | Держатель реестра |
| **Особенность** | Единственный класс, где стадия P3 вырождается: реестр утверждений содержит утверждения о **правилах ведения** реестра, а не о его записях. Записи добавляются не производством документа, а производством описываемых объектов |

### 6.3. Правило выбора класса

```
1. На какой вопрос отвечает документ? → сопоставить с таблицей 6.2.
2. Какой класс утверждений преобладает? → уточнить выбор.
3. Подходят два класса?
   → документ отвечает на два вопроса; применить R3 (разделение).
4. Не подходит ни один?
   → перечень классов неполон; требуется решение о его расширении.
      Производство до принятия решения не начинается.
```

Класс объявляется на стадии **P1** и фиксируется в карте области. Изменение класса по ходу производства — основание для возврата на P1 (R1).

### 6.4. Сводка режимов отказа

Таблица предназначена рецензенту: она сообщает, что проверять **прежде всего** для данного класса.

| Класс | Ищи в первую очередь |
|-------|----------------------|
| C1 Замысел | утверждения, не запрещающие ничего |
| C2 Наблюдение | реконструкцию, выданную за подтверждённое |
| C3 Определение | понятие, уже принадлежащее другому документу |
| C4 Модель | определение слова там, где нужна структура |
| C5 Опыт | шаг без источника; разрыв в пути |
| C6 Поведение | правило, принадлежащее модели |
| C7 Форма | конкретную величину вне владельца значений |
| C8 План | единицу, отсутствующую в реестре; нарушенный порядок зависимостей |
| C9 Реестр | описание там, где должен быть идентификатор |

### 6.5. Порядок производства классов

Классы связаны по выводимости. Производство в неверном порядке — основная причина отказов на стадии P2: источник ещё не существует.

```
C2 Наблюдение ──▶ C1 Замысел ──▶ C3 Определение ──▶ C4 Модель ──▶ C5 Опыт ──▶ C6 Поведение ──▶ C8 План
                                                                       │
                                                                       └──▶ C7 Форма

C9 Реестр — производится вместе с классом описываемых объектов
```

1. Документ НЕ ДОПУСКАЕТСЯ к производству, если документы, из которых он выводится, находятся в состоянии ниже `Approved`.
2. Исключение — стадии P0–P1: заявить область можно раньше. Стадия P2 при отсутствии источника завершается стратегией R4 (приостановка).
3. Параллельное производство документов одного класса ДОПУСКАЕТСЯ. Параллельное производство классов, связанных выводимостью, НЕ СЛЕДУЕТ: нижестоящий будет переписан.

Пункт 3 — самое частое организационное нарушение: производство опыта и поведения начинают одновременно с моделью, поскольку это кажется быстрее. Результат — переписывание обоих.

### 6.6. Что не различается по классам

Во избежание толкований: перечисленное одинаково для всех классов и НЕ ДОПУСКАЕТСЯ к изменению профилем.

| Одинаково для всех классов |
|----------------------------|
| Перечень и порядок стадий P0–P9 |
| Обязательность ворот P1, P3, P7, P9 |
| Обязательность реестра утверждений |
| Правило однократного написания прозы |
| Правило двух возвратов |
| Условия выхода X1–X12 |
| Независимость рецензента |
| Запреты для AI-агента |
