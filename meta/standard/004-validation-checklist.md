# Чек-лист валидации

> Проверка бывает двух видов: та, которую делает машина, и та, ради которой машину освободили.
>
> Стандарт требует автоматизировать первую полностью, чтобы человек тратил внимание только на смысл.

---

## 1. Purpose · Назначение

Задать минимальный обязательный набор проверок, применимый к любому документу и любому корпусу, независимо от предметной области.

## 5. Validation Rules · Правила валидации

1. Каждый пункт чек-листа имеет идентификатор, формулировку, признак автоматизируемости и действие при нарушении.
2. Каждый пункт, помеченный как автоматизируемый, реализуем без обращения к смыслу текста.
3. Ни один пункт не дублирует пункт DES-005.
4. Чек-лист версионируется; документ фиксирует версию чек-листа, который прошёл.

## 6. Content · Содержание

### 6.1. Уровни проверки

| Уровень | Что проверяется | Исполнитель | Когда |
|---------|-----------------|-------------|-------|
| **V1** | Форма документа | машина | каждое изменение |
| **V2** | Связи в графе документов | машина | каждое изменение |
| **V3** | Смысл содержания | человек | переход в `Review`, `Approved` |
| **V4** | Целостность корпуса | машина | по расписанию + перед `Canonical` |

Уровни проверяются по возрастанию. Провал уровня останавливает проверку: проверять смысл документа со сломанными ссылками бессмысленно, потому что часть утверждений может относиться к несуществующим документам.

### 6.2. V1 · Форма

| # | Проверка | Авто | При нарушении |
|---|----------|------|---------------|
| V1.1 | Присутствуют все обязательные поля метаданных, заданные привязкой | да | изменение отклоняется |
| V1.2 | Значение состояния входит в множество DES-001 | да | изменение отклоняется |
| V1.3 | Версия соответствует формату `MAJOR.MINOR.PATCH` | да | изменение отклоняется |
| V1.4 | Версия согласована с состоянием (DES-001, раздел 6.5) | да | исправить версию или состояние |
| V1.5 | Дата последнего изменения — абсолютная, в едином формате | да | изменение отклоняется |
| V1.6 | Присутствуют все обязательные разделы в заданном порядке | да | изменение отклоняется |
| V1.7 | Поле владения понятиями непусто | да | документ ничем не владеет: см. DES-002, E2 |
| V1.8 | Заявленная позиция чтения совпадает с реестром порядка | да | обновить реестр или документ |
| V1.9 | Заявленный ранг соответствует зоне по привязке | да | исправить документ |
| V1.10 | Заявленная версия стандарта поддерживается | да | миграция класса M-E (DES-015) |

### 6.3. V2 · Связи

| # | Проверка | Авто | При нарушении |
|---|----------|------|---------------|
| V2.1 | Каждая зависимость указывает на существующий документ | да | изменение отклоняется |
| V2.2 | Симметрия: зависимость и обратная ссылка объявлены с обеих сторон | да | добавить недостающую сторону |
| V2.3 | Граф зависимостей ацикличен | да | разорвать цикл выносом общего знания выше |
| V2.4 | Ни одна зависимость не направлена в нижестоящий слой | да | знание принято не на своём уровне |
| V2.5 | Каждая зависимость находится раньше в порядке чтения | да | исправить порядок |
| V2.6 | Документ в `Canonical` не зависит от документа ниже `Approved` | да | понизить состояние или продвинуть зависимость |
| V2.7 | Ни одно понятие не заявлено во владение двумя документами | да | конфликт владения: DES-009 |
| V2.8 | Каждое заявленное понятие присутствует в реестре владения | да | обновить реестр |

### 6.4. V3 · Смысл

Проверяется человеком. Автоматизации не подлежит по существу: каждый пункт требует понимания текста.

| # | Проверка | При нарушении |
|---|----------|---------------|
| V3.1 | Знание находится только в разделе содержания | перенести |
| V3.2 | Документ не определяет ничего из своего списка исключений | перенести к владельцу, оставить ссылку |
| V3.3 | Документ не пересказывает то, на что можно сослаться | заменить ссылкой |
| V3.4 | Каждое нормативное утверждение имеет источник (DES-006) | добавить источник или удалить утверждение |
| V3.5 | Каждый термин употреблён в зарегистрированном значении (DES-014) | исправить или дополнить реестр терминов |
| V3.6 | Нормативные утверждения используют модальности, заданные привязкой | переформулировать |
| V3.7 | Правила валидации документа проверяемы «да / нет» | переформулировать |
| V3.8 | Ни одно правило не существует только в диаграмме (DES-012) | вынести в текст |
| V3.9 | Примеры минимальны и не вводят новых понятий (DES-013) | сократить |
| V3.10 | Нет относительных дат и неопределённых сроков | заменить абсолютными |
| V3.11 | Неподтверждённое утверждение помечено как гипотеза | пометить или удалить |
| V3.12 | Документ отвечает на один вопрос (DES-010) | разделить |

**Правило полноты проверки V3.** Рецензент ОБЯЗАН прочитать **всё** изменённое содержание. Выборочная проверка ДОПУСКАЕТСЯ только для неизменённых частей документа.

### 6.5. V4 · Целостность корпуса

| # | Проверка | Авто | При нарушении |
|---|----------|------|---------------|
| V4.1 | Каждый документ присутствует в реестре порядка чтения | да | внести |
| V4.2 | Каждое зарегистрированное понятие имеет ровно один документ-владелец в `Canonical` | да | DES-009 |
| V4.3 | Ни один документ не пребывает в `Draft`, `Review`, `Disputed` дольше порога | да | эскалация |
| V4.4 | Каждый `Superseded` документ содержит ссылку на замену | да | добавить |
| V4.5 | Нет входящих ссылок на `Superseded` документ | да | перенаправить (DES-011) |
| V4.6 | Каждый идентификатор уникален в своей схеме | да | переназначить |
| V4.7 | Каждое записанное решение применено ко всем затронутым документам | частично | завершить применение |
| V4.8 | Доля просроченных канонических документов не превышает порог | да | запустить ревизию |
| V4.9 | Доля непрослеженных нормативных утверждений равна нулю (уровень 3) | частично | достроить прослеживаемость |
| V4.10 | Каждый файл материалов упомянут хотя бы в одном документе | да | удалить неиспользуемый |

### 6.6. Требование автоматизации

1. Каждый пункт с признаком «авто» ОБЯЗАН быть автоматизирован до заявления соответствия уровня 1 (DES-000, раздел 6.6).
2. Проверка ОБЯЗАНА выполняться до приёма изменения, а не после.
3. Результат проверки ОБЯЗАН быть воспроизводим: одно и то же состояние корпуса даёт один и тот же результат.
4. Пункт, который невозможно автоматизировать в конкретной привязке, регистрируется в реестре отклонений с обоснованием и сроком (DES-016).
5. Ручное выполнение автоматизируемой проверки НЕ ДОПУСКАЕТСЯ как постоянная практика: оно не воспроизводимо и не масштабируется.

### 6.7. Отчёт о проверке

Изменение сопровождается отчётом. Отчёт ОБЯЗАН содержать:

```
Версия чек-листа:  <версия DES-004>
Уровень V1:        пройден | провален (перечень пунктов)
Уровень V2:        пройден | провален (перечень пунктов)
Уровень V3:        пройден | провален (перечень пунктов) | не требуется
Проверил V3:       <роль рецензента; независим от автора: да/нет>
Не проверялось:    <явный перечень того, что осталось непроверенным, и почему>
```

Строка «не проверялось» ОБЯЗАТЕЛЬНА и не может быть пустой по умолчанию. Умолчание «проверено всё» скрывает пробелы; явный перечень делает их видимыми.

### 6.8. Что происходит при провале

| Уровень | Последствие |
|---------|-------------|
| V1, V2 | Изменение не принимается. Обсуждение содержания не начинается. |
| V3 | Документ возвращается в `Draft` с указанием пунктов. |
| V4 | Документ не продвигается в `Canonical`; при плановой проверке — задача держателю реестра. |

### 6.9. Версионирование чек-листа

Чек-лист версионируется вместе со стандартом. Документ фиксирует версию, которой он проверялся.

Повышение `MAJOR` стандарта требует перепроверки корпуса по новому чек-листу в рамках миграции класса M-E (DES-015). До завершения миграции документы, проверенные по прежней версии, сохраняют состояние.
