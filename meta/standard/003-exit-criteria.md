# Условия выхода — завершённость документа

> «Готово» — самое опасное слово в документации. Оно означает «я больше не собираюсь это писать», а не «документ выполняет свою задачу».
>
> Этот документ заменяет ощущение готовности на проверяемое условие.

---

## 1. Purpose · Назначение

Определить, при каких условиях документ может продвинуться по жизненному циклу, и сделать эти условия независимыми от мнения автора.

## 5. Validation Rules · Правила валидации

1. Каждое условие X1–X12 проверяемо ответом «да / нет».
2. Каждое условие указывает, чем подтверждается его выполнение.
3. Ни одно условие не может быть подтверждено автором в одиночку на переходе в `Approved`.

## 6. Content · Содержание

### 6.1. Принцип: завершённость не определяется объёмом

Документ завершён, когда выполняет заявленную задачу, а не когда исчерпана тема. Длинный документ может быть незавершён; короткий — завершён.

Единственный источник определения завершённости конкретного документа — его собственные правила валидации, сформулированные при создании (DES-002, E8). Условия ниже дополняют их и применяются ко всем документам.

### 6.2. Условия выхода

| # | Условие | Подтверждается |
|---|---------|----------------|
| **X1** | Все правила валидации самого документа выполнены | построчная проверка, результат зафиксирован |
| **X2** | Каждое заявленное понятие действительно определено в содержании | сверка заявки на владение с содержанием |
| **X3** | Ни одно понятие из списка исключений не определено в документе | сверка списка исключений с содержанием |
| **X4** | Каждое нормативное утверждение прослежено к источнику | таблица вывода (DES-006) |
| **X5** | Чек-лист валидации пройден | отчёт проверки, уровни 1–3 (DES-004) |
| **X6** | Чек-лист перекрёстных ссылок пройден | отчёт проверки (DES-005) |
| **X7** | Каскад зависимых документов обойдён, состояние каждого определено | список зависимых с отметкой по каждому |
| **X8** | Бюджет ответственности не превышен | измерение по DES-010 |
| **X9** | Диаграммы соответствуют правилам | проверка по DES-012 |
| **X10** | Примеры соответствуют правилам | проверка по DES-013 |
| **X11** | Терминология соответствует правилам | проверка по DES-014 |
| **X12** | Открытых вопросов внутри документа нет | поиск незакрытых пометок |

### 6.3. Завершённость по состояниям

Условия применяются нарастающе.

| Переход | Обязательные условия | Кто подтверждает |
|---------|----------------------|------------------|
| `Draft → Review` | X1, X2, X3, X12 | владелец |
| `Review → Approved` | X1–X12 полностью | **рецензент**, независимый от автора |
| `Approved → Canonical` | X1–X12 + регистрация понятий + каноничность всех зависимостей | держатель реестра |

Разделение по состояниям существенно: до `Review` документ отвечает только за себя, после — за своё место в корпусе.

### 6.4. Независимость рецензента

1. Рецензент НЕ ДОПУСКАЕТСЯ совпадающим с автором изменения.
2. Если автор — AI-агент, рецензентом ОБЯЗАН быть человек (DES-008).
3. Если владелец является единственным носителем компетенции, рецензентом назначается держатель реестра; проверяются форма, связи и прослеживаемость, но не предметная правильность. Такой документ помечается как проверенный частично.
4. Самопроверка ДОПУСКАЕТСЯ только для перехода `Draft → Review`.

Правило существует потому, что автор проверяет соответствие текста своему замыслу, а рецензент — соответствие текста задаче. Это разные проверки, и первая никогда не заменяет вторую.

### 6.5. Доказательство вместо утверждения

Условие выхода считается выполненным, только если зафиксировано **чем именно** оно подтверждено.

| Форма | Оценка |
|-------|--------|
| «Проверено» | не принимается |
| «X5: проверка формы — пройдена; уровень 3 — 12 пунктов, 12 выполнено» | принимается |
| «X7: 4 зависимых документа; 3 не затронуты, 1 обновлён до 1.2.0» | принимается |
| «Всё в порядке» | не принимается |

Результаты проверки сохраняются вместе с изменением. Утверждение без доказательства не отличимо от невыполненной проверки.

### 6.6. Частичная завершённость

Документ НЕ ДОПУСКАЕТСЯ переводить в `Approved` при наличии незакрытых мест в содержании.

Незакрытые вопросы обрабатываются одним из способов:

| Способ | Когда применим |
|--------|----------------|
| Вынести в реестр открытых вопросов | вопрос требует внешнего подтверждения |
| Сузить зону документа | вопрос относится к другому документу |
| Пометить как гипотезу | ответ предполагается, но не подтверждён (DES-006) |
| Разделить документ | завершена часть, соответствующая отдельному вопросу (DES-011) |

Пометка «дописать позже» внутри принятого документа НЕ ДОПУСКАЕТСЯ: она невидима для читателя, опирающегося на документ.

### 6.7. Отказ в завершении

Рецензент, отказывая, ОБЯЗАН указать:

1. номер невыполненного условия (X1–X12) или номер правила документа;
2. конкретное место;
3. что должно измениться, чтобы условие выполнялось.

Отказ без ссылки на условие не является отказом: он не проверяем и не может быть закрыт.

### 6.8. Пересмотр после изменений

Изменение уже принятого документа возвращает его на соответствующую стадию:

| Класс изменения | Возврат | Условия к повторной проверке |
|-----------------|---------|------------------------------|
| `PATCH` | не требуется | X6 (ссылки), если менялись ссылки |
| `MINOR` | `Review` не обязателен | X1, X4, X5, X6, X7 |
| `MAJOR` | обязателен возврат в `Draft` | X1–X12 полностью |

### 6.9. Завершённость документа-скелета

Документ в состоянии `Scaffold` имеет собственный критерий завершённости: выполнены все условия входа DES-002, включая сформулированные правила валидации.

Скелет **завершён как скелет** и не считается недоделанным документом. Он выполняет свою задачу — занимает место в структуре и объявляет контракт — до того, как появится содержание.
