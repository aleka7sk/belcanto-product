# Прослеживаемость утверждений

> Главная опасность документации, которая является источником истины, — **правдоподобная выдумка**. Она не отличима от факта: тот же тон, то же место, та же уверенность.
>
> Единственная защита — требовать источник у каждого утверждения. Утверждение без источника не запрещено потому, что оно ложно; оно запрещено потому, что его нельзя проверить.

---

## 1. Purpose · Назначение

Сделать происхождение каждого нормативного утверждения явным и проверяемым, а появление утверждений без источника — обнаружимым.

## 5. Validation Rules · Правила валидации

1. Каждый класс утверждений раздела 6.1 имеет определённое требование к источнику.
2. Каждое нормативное утверждение корпуса относится ровно к одному классу.
3. Форма таблицы вывода (6.4) достаточна для вычисления зоны влияния изменения.

## 6. Content · Содержание

### 6.1. Классы утверждений

| Класс | Что это | Требуемый источник | Пример формы |
|-------|---------|--------------------|--------------|
| **A · Выведенное** | следует из вышестоящего документа | ссылка на вышестоящий документ и его раздел | «поэтому X ОБЯЗАН…» |
| **B · Решённое** | результат выбора между вариантами | ссылка на записанное решение | «принято, что X…» |
| **C · Наблюдённое** | факт о внешней реальности | указание источника наблюдения, способа и даты подтверждения | «сегодня X происходит так…» |
| **D · Определяющее** | вводит понятие | сам документ; ОБЯЗАН быть владельцем понятия | «X — это…» |
| **E · Пояснительное** | не нормативно, служит пониманию | источник не требуется | «иначе говоря…» |

**Правило полноты.** Каждое утверждение класса A, B, C, D ОБЯЗАНО иметь источник в требуемой форме. Утверждение, не относимое ни к одному классу, — выдумка и подлежит удалению.

**Правило класса E.** Пояснение НЕ ДОПУСКАЕТСЯ несущим норму. Если удаление пояснения меняет обязательства читателя — это не пояснение, а утверждение класса A–D без источника.

### 6.2. Что не является источником

| Форма | Почему не принимается |
|-------|-----------------------|
| «Общепринято» | не проверяемо, не имеет адреса |
| «Очевидно, что» | скрывает отсутствие вывода |
| «Лучшая практика» | без указания чьей и где зафиксированной |
| «Так решили» | без ссылки на записанное решение |
| Ссылка на устный разговор | не воспроизводима; ОБЯЗАНА быть сначала записана как решение или наблюдение |
| Ссылка на документ ниже `Approved` | источник сам не является истиной |
| Ссылка на нижестоящий слой | нарушение направления вывода (DES-005) |
| Внешний источник как единственное основание | внешние ресурсы меняются и исчезают (DES-005) |

### 6.3. Гипотезы

Утверждение, для которого источник предполагается, но не подтверждён, ДОПУСКАЕТСЯ при выполнении всех условий:

1. Помечено как гипотеза непосредственно в месте употребления, а не в примечании к документу.
2. Зарегистрировано в реестре открытых вопросов привязки.
3. Указана роль, отвечающая за подтверждение.
4. Ни один документ не выводит из гипотезы утверждение класса A.
5. Документ, содержащий гипотезу в нормативной части, НЕ ДОПУСКАЕТСЯ переводить в `Canonical`.

Гипотеза — легальное состояние знания. Незамеченная гипотеза — нет.

### 6.4. Таблица вывода

Каждый документ, содержащий нормативные утверждения, ОБЯЗАН завершать раздел содержания таблицей вывода.

```
| Раздел | Класс | Источник | Версия источника |
|--------|-------|----------|------------------|
| 6.2    | A     | <документ>, раздел 6.4 | 2.1.0 |
| 6.3    | B     | <решение №>            | —     |
| 6.5    | C     | <источник наблюдения>, подтверждено <дата> | — |
| 6.7    | D     | собственное определение | —    |
```

Требования:

1. Гранулярность — **раздел**, а не отдельное предложение. Пофразовая прослеживаемость делает документ нечитаемым и на практике не поддерживается.
2. Раздел, содержащий утверждения нескольких классов, представлен несколькими строками.
3. Версия источника указывается для класса A, если утверждение чувствительно к изменению источника.
4. Раздел без строки в таблице считается непрослеженным.

### 6.5. Прослеживаемость как свойство корпуса

Прослеживаемость двунаправленна:

```
вниз:  документ ──> его источники          (таблица вывода)
вверх: документ ──> его потребители        (каскадные ссылки, DES-005)
```

Оба направления ОБЯЗАНЫ быть полны. Вниз — чтобы проверить обоснованность. Вверх — чтобы вычислить последствия изменения.

### 6.6. Анализ влияния изменения

Зона влияния изменения документа **X** вычисляется по графу без чтения текста:

```
1. Прямое влияние    = все документы, объявившие X зависимостью
2. Косвенное влияние = транзитивное замыкание шага 1
3. Цитатное влияние  = все документы, цитирующие X (для MAJOR)
4. Реестровое влияние= все реестры, содержащие идентификаторы X
5. Зона влияния      = объединение 1–4
```

Требования:

1. Изменение класса `MAJOR` ОБЯЗАНО сопровождаться вычисленной зоной влияния.
2. Каждый документ прямого влияния ОБЯЗАН быть проверен с фиксацией исхода.
3. Документы косвенного влияния СЛЕДУЕТ проверять; при отказе от проверки причина фиксируется.
4. Невычислимая зона влияния означает неполный граф — дефект уровня корпуса, а не документа.

### 6.7. Отметка о проверке каскада

Для обнаружения устаревания (DES-009) каждая каскадная связь ОБЯЗАНА нести отметку: версия зависимости, при которой проверка выполнялась в последний раз.

```
Зависимости и отметка проверки:
  <документ A> @ 2.1.0
  <документ B> @ 1.0.0
```

Если текущая версия зависимости выше отмеченной, документ считается **потенциально устаревшим** и попадает в отчёт. Это единственный механизм, обнаруживающий незавершённый каскад автоматически: без него пропущенный обход зависимых документов остаётся невидимым до следующего чтения.

### 6.8. Метрика покрытия

| Метрика | Определение | Требование по уровням соответствия |
|---------|-------------|------------------------------------|
| Покрытие вывода | доля разделов с нормативными утверждениями, имеющих строку в таблице вывода | уровень 2: ≥ порога привязки; уровень 3: 100 % |
| Свежесть каскада | доля каскадных связей, отметка которых равна текущей версии зависимости | уровень 3: 100 % |
| Незакрытые гипотезы | число гипотез в документах `Canonical` | уровень 3: 0 |

### 6.9. Прослеживаемость и AI-агенты

Требование источника — основное ограничение, накладываемое на AI-агента (DES-008).

1. Агент НЕ ДОПУСКАЕТСЯ к написанию утверждения класса A, B, C без указания конкретного источника.
2. При отсутствии источника агент ОБЯЗАН зарегистрировать открытый вопрос, а не сформулировать правдоподобное утверждение.
3. Агент ОБЯЗАН отдельно перечислять утверждения, источник которых он не смог подтвердить.
4. Заполнение пробела правдоподобным текстом — наиболее вероятный и наиболее дорогой вид отказа при работе агента с документацией: результат выглядит корректно и проходит все проверки формы.
