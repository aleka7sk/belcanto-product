# Documentation Engineering Standard — обзор

> DES — переиспользуемый стандарт производства документации, которая является источником истины.
>
> Стандарт не описывает никакой продукт. Он описывает, **как документы создаются, проверяются, изменяются и выводятся из обращения** так, чтобы корпус документов оставался непротиворечивым при неограниченном росте и при участии AI-агентов.

---

## 1. Purpose · Назначение

Дать инженерную дисциплину производства документации: набор критериев, протоколов и проверок, при соблюдении которых любой новый документ гарантированно

- внутренне непротиворечив;
- выведен только из авторитетных источников;
- не дублирует существующее знание;
- пригоден для расширения AI-агентом;
- устойчив к последующей эволюции предметной области.

Без стандарта эти свойства зависят от аккуратности конкретного автора. Со стандартом они проверяемы.

---

## 2. Owner · Владелец

- **Standard Maintainer** — содержание стандарта, его версия, приём отклонений.

Роль, а не человек. Стандарт не принадлежит команде продукта: он переиспользуется.

## 4. Reading Order · Место в порядке чтения

Позиция **0.11** — первый документ стандарта.

Стандарт читается **перед первым авторством**, а не перед первым чтением репозитория. Тот, кто только читает документацию, стандарт может пропустить. Тот, кто пишет, — не может.

---

## 5. Validation Rules · Правила валидации

1. Каждый документ стандарта присутствует в карте раздела 6.4.
2. Ни один документ стандарта не содержит названий, специфичных для конкретного продукта или репозитория.
3. Каждая нормативная формулировка стандарта использует модальность из раздела 6.2.
4. Каждое требование стандарта либо проверяемо автоматически, либо содержит явное указание «проверяется человеком».

## 6. Content · Содержание

### 6.1. Область действия

DES применим к любому репозиторию, в котором документация является **источником истины**, а не сопровождением кода.

**Стандарт определяет:**

| Область | Документ |
|---------|----------|
| Жизненный цикл документа | DES-001 |
| Условия входа (создание) | DES-002 |
| Условия выхода (завершённость) | DES-003 |
| Проверка документа | DES-004 |
| Проверка перекрёстных ссылок | DES-005 |
| Прослеживаемость утверждений | DES-006 |
| Владение и его передача | DES-007 |
| Протокол изменений AI-агентом | DES-008 |
| Обнаружение конфликтов | DES-009 |
| Бюджет ответственности документа | DES-010 |
| Декомпозиция и слияние | DES-011 |
| Диаграммы | DES-012 |
| Примеры | DES-013 |
| Терминология | DES-014 |
| Миграции | DES-015 |
| Соответствие и привязка | DES-016 |

**Стандарт НЕ определяет** (это зона привязки, DES-016):

- модель слоёв и зон конкретного репозитория;
- порядок авторитета документов;
- каталог ролей;
- конкретный набор полей frontmatter;
- схемы идентификаторов;
- числовые пороги;
- инструментарий проверки;
- предметную область.

### 6.2. Нормативные модальности

Стандарт использует три модальности. Они имеют точный смысл и не являются стилистическими вариантами.

| Модальность | Смысл | Нарушение |
|-------------|-------|-----------|
| **ОБЯЗАН** / ОБЯЗАНО / НЕ ДОПУСКАЕТСЯ | Абсолютное требование | документ не соответствует стандарту |
| **СЛЕДУЕТ** / НЕ СЛЕДУЕТ | Требование, отступление от которого допустимо только с записанным обоснованием | требуется запись в реестре отклонений (DES-016) |
| **ДОПУСКАЕТСЯ** | Разрешение, а не рекомендация | нарушить невозможно |

Любая формулировка стандарта, не содержащая модальности, является пояснением и не нормативна.

### 6.3. Принципы, на которых построен стандарт

| # | Принцип | Следствие |
|---|---------|-----------|
| P1 | **Документ — инженерный артефакт** | у него есть жизненный цикл, критерии приёмки и владелец |
| P2 | **Завершённость определяется до написания** | условия выхода документа формулируются в момент его создания |
| P3 | **Каждое утверждение имеет источник** | утверждение без источника — выдумка, а не документация |
| P4 | **Знание имеет ровно одного владельца** | всё остальное — ссылка |
| P5 | **Обнаружение отделено от разрешения** | конфликт находится автоматически, разрешается человеком |
| P6 | **Форма проверяема машиной** | человеческая проверка тратится только на смысл |
| P7 | **Изменение завершается каскадом** | правка без обхода зависимых документов не считается сделанной |
| P8 | **Агент предлагает, роль принимает** | AI никогда не переводит документ в авторитетное состояние |
| P9 | **Стандарт — пол, а не потолок** | привязка ужесточает, но не ослабляет |

### 6.5. Привязка

**Стандарт сам по себе неработоспособен.** Он оперирует абстракциями: «авторитетный источник», «зона документа», «владеющая роль», «порог». Конкретные значения даёт **привязка** (binding) — набор документов репозитория, реализующих требования DES-016.

```
DES (переиспользуемый, продуктово-нейтральный)
        ↓ реализуется
Привязка (конкретный репозиторий: слои, ранги, роли, поля, пороги)
        ↓ применяется к
Документы репозитория
```

Отсутствие привязки означает, что соответствие стандарту не может быть заявлено.

### 6.6. Уровни соответствия

| Уровень | Название | Что гарантирует | Критерий |
|---------|----------|-----------------|----------|
| **1** | Форма | Документы единообразны и связны | DES-001…005 соблюдаются; проверка формы автоматизирована |
| **2** | Прослеживаемость | Каждое утверждение имеет источник, изменения каскадируются | уровень 1 + DES-006, 007, 009; граф зависимостей полон и симметричен |
| **3** | Каноничность | Корпус пригоден как единственный источник истины; агент работает детерминированно | уровень 2 + DES-008, 010…015; доля непрослеженных утверждений = 0; открытых конфликтов старше срока нет |

Уровень заявляется репозиторием явно и проверяется. Заявленный, но не проверенный уровень считается недействительным.

### 6.7. Версионирование стандарта

Стандарт версионируется по `MAJOR.MINOR.PATCH`:

| Часть | Повышается | Последствие для репозитория |
|-------|------------|------------------------------|
| `MAJOR` | требование ужесточено или удалено; прежнее соответствие недействительно | обязательна миграция класса M-E (DES-015) |
| `MINOR` | добавлено новое требование, не отменяющее прежние | миграция в течение окна совместимости |
| `PATCH` | уточнение формулировки без изменения смысла | действий не требуется |

Каждый документ репозитория, заявляющий соответствие, ОБЯЗАН фиксировать версию стандарта, которой он соответствует.

### 6.8. Как этот стандарт извлечь и переиспользовать

Каталог `meta/standard/` самодостаточен: документы стандарта ссылаются только друг на друга. Перенос в другой репозиторий состоит из двух шагов:

1. скопировать каталог целиком;
2. создать привязку по DES-016, раздел 6.2.

Ссылка из документа стандарта на что-либо вне `meta/standard/` — дефект стандарта и подлежит устранению.
