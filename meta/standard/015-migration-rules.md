# Правила миграций

> Отдельный документ изменяется правкой. Соглашение, действующее во всём корпусе, правкой изменить нельзя: в промежутке часть документов следует прежнему соглашению, часть — новому, и обе части выглядят корректными.
>
> Миграция — способ провести такое изменение так, чтобы смешанное состояние было объявленным, ограниченным по времени и завершаемым.

---

## 1. Purpose · Назначение

Обеспечить возможность изменять саму систему документации — поля, структуру, термины, границы документов, версию стандарта — без утраты целостности корпуса и без бессрочного смешанного состояния.

## 6. Content · Содержание

### 6.1. Что является миграцией

Миграция — изменение, затрагивающее **соглашение**, а не содержание: то, что применяется к множеству документов и делает прежнюю форму или прежний смысл недействительными.

| Это миграция | Это правка |
|--------------|------------|
| Добавление обязательного поля метаданных | Заполнение поля в одном документе |
| Переименование термина | Уточнение определения без изменения смысла |
| Изменение модели слоёв | Перенос одного документа между слоями |
| Разделение или слияние документов | Изменение раздела документа |
| Повышение версии стандарта | Изменение содержания по существующим правилам |
| Изменение схемы идентификаторов | Выдача нового идентификатора |
| Перенумерация разделов документа | Добавление раздела в конец |

Признак миграции: **невозможно выполнить одним изменением одного документа, не создав временного несоответствия**.

### 6.2. Классы миграций

| Класс | Что меняется | Основной риск |
|-------|--------------|---------------|
| **M-A · Схема** | состав или смысл полей метаданных | документы старого образца проходят проверки, но не несут нужных данных |
| **M-B · Таксономия** | модель слоёв, зон, рангов, порядок чтения | нарушается направление зависимостей |
| **M-C · Терминология** | имя, смысл или владелец термина | расходятся употребления в неизменённых документах |
| **M-D · Структура** | разделение, слияние, перемещение документов | обрываются входящие ссылки |
| **M-E · Стандарт** | версия стандарта или чек-листов | прежнее соответствие недействительно |
| **M-F · Пересборка** | повторный вывод содержания после изменения источника | часть документов выведена из старой редакции источника |

### 6.3. Обязательный состав плана

Миграция НЕ ДОПУСКАЕТСЯ к началу без плана. План ОБЯЗАН содержать:

```
Идентификатор:        <устойчивый идентификатор миграции>
Класс:                M-A | M-B | M-C | M-D | M-E | M-F
Основание:            <что делает изменение необходимым; ссылка на решение>

Область:              <ПЕРЕЧИСЛЕННЫЙ список документов, а не описание>
Вне области:          <документы, которых миграция не касается, и почему>

Отображение:          <соответствие «прежняя форма → новая форма»>
Окно совместимости:   <срок, в течение которого обе формы допустимы>

Порядок исполнения:   <партии в порядке применения>
Автоматизация:        <что выполняется скриптом; где скрипт хранится>
Ручная часть:         <что требует человека и почему>

Проверка завершения:  <проверки, подтверждающие завершение>
Откат:                <как вернуться к прежнему состоянию до точки невозврата>
Точка невозврата:     <после какой партии откат невозможен>
Ответственный:        <роль>
```

**Область перечисляется, а не описывается.** Формулировка «все документы, содержащие X» непроверяема на завершённость: невозможно доказать, что найдены все.

### 6.4. Окно совместимости

1. Каждая миграция ОБЯЗАНА иметь окно, в течение которого прежняя и новая формы одинаково допустимы.
2. Окно ОБЯЗАНО быть ограничено сроком. Бессрочное окно превращает смешанное состояние в постоянное.
3. В течение окна отображение «прежняя форма → новая» является нормативным: по нему выполняются проверки и разрешаются вопросы.
4. Новые документы, создаваемые в течение окна, ОБЯЗАНЫ использовать только новую форму.
5. По завершении окна прежняя форма становится нарушением, обнаруживаемым проверками.
6. Продление окна ДОПУСКАЕТСЯ один раз с фиксацией причины. Повторное продление — признак того, что миграция не будет завершена, и требует решения о её отмене.

### 6.5. Порядок исполнения

| # | Правило |
|---|---------|
| E1 | Миграция выполняется партиями, а не целиком |
| E2 | Партии формируются **от корня графа зависимостей наружу**: сначала документы, от которых зависят другие |
| E3 | Партия ОБЯЗАНА оставлять корпус в проверяемом состоянии: симметрия связей и реестры целостны на границе каждой партии |
| E4 | Внутри партии изменение атомарно |
| E5 | Между партиями ДОПУСКАЕТСЯ пауза; смешанное состояние легально в пределах окна |
| E6 | Две миграции НЕ ДОПУСКАЮТСЯ одновременно к одному документу |
| E7 | Механическая часть ОБЯЗАНА выполняться скриптом; скрипт хранится вместе с планом |
| E8 | Скрипт ОБЯЗАН быть повторно применимым: повторный запуск не меняет уже мигрированное |

E2 существенно: миграция от листьев к корню оставляет корень несогласованным с уже мигрированными потребителями на протяжении всей операции.

E7 — не удобство. Ручная механическая миграция даёт разный результат в разных документах, и расхождения обнаруживаются годами.

### 6.6. Роль AI-агента

1. Агенту СЛЕДУЕТ поручать исполнение механической части по утверждённому плану: это работа, требующая полноты, а не суждения.
2. Агент НЕ ДОПУСКАЕТСЯ к утверждению плана миграции.
3. Агент НЕ ДОПУСКАЕТСЯ к расширению области миграции по ходу исполнения. Обнаруженный документ вне перечисленной области регистрируется как отклонение и передаётся ответственному.
4. Агент ОБЯЗАН отчитаться о каждой партии: что изменено, что пропущено, что потребовало решения.
5. Изменения миграции относятся к классу C или D (DES-008) независимо от их механической простоты.

### 6.7. Завершённость

Миграция считается завершённой при выполнении **всех** условий:

| # | Условие |
|---|---------|
| C1 | Каждый документ перечисленной области приведён к новой форме |
| C2 | Ни один документ вне области не изменён |
| C3 | Проверки завершения из плана выполнены и зафиксированы |
| C4 | Окно совместимости закрыто |
| C5 | Прежняя форма перестала быть допустимой; проверки обновлены |
| C6 | Отклонения, обнаруженные при исполнении, разрешены или зарегистрированы |
| C7 | Запись в реестре миграций закрыта с датой и результатом |

Незакрытая миграция сохраняет корпус в смешанном состоянии и блокирует другие миграции того же класса (E6).

### 6.8. Отмена и откат

1. План ОБЯЗАН определять точку невозврата — партию, после которой откат невозможен.
2. До точки невозврата откат выполняется как обратная миграция с собственным планом, а не как отмена изменений.
3. После точки невозврата возврат к прежнему состоянию выполняется только новой миграцией.
4. Отменённая миграция сохраняется в реестре с указанием причины: она объясняет, почему часть корпуса выглядит несогласованной.

### 6.9. Реестр миграций

Привязка ОБЯЗАНА вести реестр миграций. Реестр содержит:

| Поле | Назначение |
|------|------------|
| Идентификатор | ссылка из документов и записей решений |
| Класс | сопоставление с правилами исполнения |
| Состояние | запланирована / исполняется / завершена / отменена |
| Область | перечень документов |
| Окно | даты начала и окончания |
| Ответственный | роль |
| Результат | что достигнуто, что осталось |

Записи реестра НЕ ДОПУСКАЮТСЯ к удалению: реестр объясняет происхождение текущей формы корпуса.

### 6.10. Устойчивость к эволюции

Совокупность правил обеспечивает свойство, ради которого стандарт существует: **корпус может менять собственные соглашения, не теряя связности**.

| Свойство | Обеспечивается |
|----------|----------------|
| Смешанное состояние допустимо | окном совместимости (6.4) |
| Смешанное состояние конечно | ограничением срока окна (6.4) |
| Незавершённая миграция видна | критерием завершённости (6.7) и реестром (6.9) |
| Пропущенный документ обнаруживается | перечисленной областью (6.3) |
| Результат воспроизводим | требованием автоматизации (6.5, E7) |
| Причина текущей формы известна | неудаляемым реестром (6.9) |
