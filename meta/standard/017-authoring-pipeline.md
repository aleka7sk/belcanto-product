# Конвейер производства документа

> Документ не пишут. Документ **производят**: последовательностью стадий, каждая из которых даёт проверяемый артефакт и заканчивается воротами.
>
> Причина не в бюрократии. Переписывание возникает тогда, когда решение, принятое поздно, обесценивает работу, сделанную рано. Конвейер выносит все решения **выше** первой написанной фразы.

---

## 1. Purpose · Назначение

Задать порядок производства документа, при котором проза пишется один раз, а всякое решение, способное её обесценить, принимается и проверяется до того, как она написана.

## 5. Validation Rules · Правила валидации

1. Каждая стадия P0–P9 имеет определённые артефакт, ворота и ответственную роль.
2. Каждая стадия указывает условия отказа и допустимые стратегии восстановления.
3. Ни одна стадия не переопределяет состояния и переходы DES-001.
4. Соответствие стадий и состояний (раздел 6.4) покрывает все состояния жизненного цикла до `Canonical`.
5. Множество стратегий восстановления (раздел 6.8) замкнуто: каждый отказ разрешается стратегией из него.

## 6. Content · Содержание

### 6.1. Основное правило

**Проза пишется один раз.**

Из него следуют три запрета:

| # | Запрет |
|---|--------|
| W1 | Написание содержания до утверждения реестра утверждений (стадия P3) НЕ ДОПУСКАЕТСЯ |
| W2 | Написание содержания для утверждения, не прошедшего ворота P3, НЕ ДОПУСКАЕТСЯ |
| W3 | Исправление содержания в обход реестра утверждений НЕ ДОПУСКАЕТСЯ: сначала меняется утверждение, затем — проза, выведенная из него |

W3 — не формальность. Правка прозы «на месте» рвёт связь между текстом и его источником, и прослеживаемость (DES-006) восстанавливается уже вручную.

### 6.2. Лестница стоимости

Стадии упорядочены по возрастанию стоимости отказа. Ворота каждой стадии существуют, чтобы отказ произошёл **раньше**, а не позже.

| Стадия | Артефакт | Стоимость отказа здесь | Стоимость того же отказа на P7 |
|--------|----------|------------------------|--------------------------------|
| P0 Запрос | заявка на производство | минуты | документ не должен был существовать |
| P1 Область | карта области | минуты | документ отвечает не на тот вопрос |
| P2 Источники | досье источников | часы | утверждения не на что опереть |
| P3 Утверждения | реестр утверждений | часы | **переписывание целиком** |
| P4 Структура | скелет документа | часы | перекомпоновка всей прозы |
| P5 Черновик | проза | дни | — |
| P6 Самопроверка | отчёт проверки | часы | — |
| P7 Рецензия | вердикт | дни | — |
| P8 Интеграция | запись интеграции | часы | — |
| P9 Канонизация | запись регистрации | минуты | — |

**Правило раннего отказа.** Отказ, возможный на стадии N, НЕ ДОПУСКАЕТСЯ откладывать до стадии N+1. Ворота, пропустившие то, что обязаны были задержать, — дефект ворот, а не рецензента.

Правый столбец объясняет, зачем нужен весь конвейер: разница между «часы» и «переписывание целиком» — это вся его окупаемость.

### 6.3. Конвейер

```
P0 Запрос ──▶ P1 Область ──▶ P2 Источники ──▶ P3 Утверждения ──▶ P4 Структура
   ▲              ▲                ▲                 ▲                 │
   │              │                │                 │                 ▼
   │              │                │                 │            P5 Черновик
   │              │                │                 │                 │
   │              │                │                 │                 ▼
   │              │                │                 │            P6 Самопроверка
   │              │                │                 │                 │
   │              │                │                 │                 ▼
   └──────────────┴────────────────┴─────────────────┴───────────  P7 Рецензия
        возврат по стратегии восстановления (раздел 6.8)               │
                                                                       ▼
                                                                  P8 Интеграция
                                                                       │
                                                                       ▼
                                                                  P9 Канонизация
```

Ни один документ не существует как файл до стадии **P4**. Стадии P0–P3 производят артефакты, а не документ. Это и есть операционный смысл требования «документ не пишут напрямую».

### 6.4. Соответствие стадий и состояний

Состояния и переходы принадлежат [`001-document-lifecycle.md`](001-document-lifecycle.md). Конвейер не вводит новых состояний — он показывает, чем занята роль внутри каждого.

| Стадия | Состояние документа | Переход DES-001 |
|--------|---------------------|-----------------|
| P0–P3 | файла не существует | — |
| P4 | `Scaffold` | T1 |
| P5 | `Draft` | T2 |
| P6 | `Draft` | — (завершается запросом на переход) |
| P7 | `Review` | T3, далее T4 или T5 |
| P8 | `Approved` | T5 состоялся |
| P9 | `Canonical` | T6 |

### 6.5. Артефакты

Каждая стадия даёт артефакт. Артефакт сохраняется — он является свидетельством при последующем споре о зоне, источниках или намерении документа.

| Артефакт | Стадия | Форма | Срок хранения |
|----------|--------|-------|---------------|
| Заявка на производство | P0 | структурированная запись | до вывода документа из обращения |
| Карта области | P1 | заявка на создание DES-002, раздел 6.10 | постоянно |
| Досье источников | P2 | перечень с закреплёнными версиями | до следующей ревизии |
| **Реестр утверждений** | P3 | таблица утверждений | постоянно; изменяется вместе с документом |
| Скелет | P4 | файл документа, разделы 1–5 | становится документом |
| Черновик | P5 | раздел 6 документа | становится документом |
| Отчёт самопроверки | P6 | отчёт DES-004, раздел 6.7 | до следующего изменения |
| Вердикт рецензии | P7 | структурированная запись | постоянно |
| Запись интеграции | P8 | перечень каскада с исходами | до следующего изменения |
| Запись регистрации | P9 | строки реестров | постоянно |

**Реестр утверждений — центральный артефакт конвейера.** Он живёт дольше черновика и переживает переписывание документа: содержание может быть изложено иначе, но перечень утверждений и их источников остаётся тем же, пока не принято решение его изменить.

### 6.6. Реестр утверждений

Реестр утверждений — плоский перечень всего, что документ намерен утверждать, составленный **до** написания прозы.

Каждая строка ОБЯЗАНА содержать:

| Поле | Содержание |
|------|------------|
| Номер | устойчивый номер утверждения внутри документа |
| Утверждение | одно предложение; то, что читатель обязан считать верным |
| Класс | A выведенное · B решённое · C наблюдённое · D определяющее (DES-006) |
| Источник | конкретный документ и раздел, решение или наблюдение |
| Версия источника | для класса A |
| Модальность | нормативное · пояснительное |
| Понятие | какое из понятий документа затрагивает |
| Состояние | предложено · утверждено · отклонено · отложено |

Требования:

1. Утверждение формулируется **одним предложением**. Не поместившееся в одно предложение — два утверждения.
2. Утверждение без источника НЕ ДОПУСКАЕТСЯ к утверждению; оно либо отклоняется, либо становится гипотезой и регистрируется (DES-006, раздел 6.3).
3. Утверждение вне объявленной зоны документа отклоняется на воротах P3, а не в рецензии.
4. Реестр утверждается целиком. Частично утверждённый реестр не открывает стадию P5.
5. После утверждения реестр становится **контрактом черновика**: проза излагает утверждения реестра и ничего сверх них.

**Почему это работает.** Реестр утверждений отделяет *что документ говорит* от *как он это говорит*. Первое — предмет решения и главный источник переписывания. Второе — ремесло, и оно дёшево. Рецензент, читающий реестр на 30 строк, обнаруживает несогласие с рамкой за полчаса; тот же рецензент, читающий готовый документ, обнаруживает его через неделю и после чужой недельной работы.

### 6.7. Типы ворот

| Тип | Смысл | Поведение |
|-----|-------|-----------|
| **Жёсткие** | Условие обязательно | переход к следующей стадии невозможен |
| **Мягкие** | Условие желательно | переход возможен с записанным риском в артефакте стадии |
| **Останавливающие** | Обнаружено препятствие вне компетенции стадии | конвейер приостанавливается, применяется стратегия восстановления |

1. Ворота P1, P3, P7, P9 ОБЯЗАНЫ быть жёсткими.
2. Мягкие ворота ОБЯЗАНЫ фиксировать принятый риск. Мягкие ворота без записи риска равносильны отсутствию ворот.
3. Пропуск ворот НЕ ДОПУСКАЕТСЯ. Ускорение достигается сокращением объёма стадии, а не отказом от неё.

### 6.8. Стратегии восстановления

Множество замкнуто: каждый отказ разрешается **ровно одной** из шести стратегий. Замкнутость делает поведение при отказе предсказуемым и позволяет поручать реакцию агенту.

| # | Стратегия | Когда | Куда ведёт |
|---|-----------|-------|------------|
| **R1 · Возврат** | обнаружено, что решение предыдущей стадии неверно | к указанной стадии; артефакты после неё аннулируются |
| **R2 · Сужение** | область больше, чем поддаётся производству | к P1; часть выносится в отдельную заявку |
| **R3 · Разделение** | документ отвечает на два вопроса | к P1 по DES-011; порождает две заявки |
| **R4 · Приостановка** | требуется внешний ответ | стадия замораживается; вопрос — в реестр открытых вопросов |
| **R5 · Эскалация** | требуется решение роли | ожидание записанного решения; конвейер не движется |
| **R6 · Отказ** | документ не должен существовать | производство прекращается; заявка закрывается с причиной |

**Правило двух возвратов.** Стадия, отклонённая **дважды подряд**, НЕ ДОПУСКАЕТСЯ к третьей попытке в том же виде. Применяется R2, R3 или R5.

Правило существует против самого дорогого сценария — колебания между двумя стадиями. Повторный отказ означает, что расходятся не формулировки, а понимание задачи, и это разрешается решением, а не следующей попыткой.

### 6.9. Закрепление источников

Источники, собранные на P2, закрепляются по версиям и остаются закреплёнными до P8.

1. Досье источников ОБЯЗАНО фиксировать версию каждого источника.
2. Изменение источника в ходе производства обнаруживается детектором несовпадения версии (DES-009, A9) на стадии P8.
3. Обнаруженное расхождение обрабатывается по стратегии R1 с возвратом на P2 или P3 — **но не позднее**: расхождение, обнаруженное после P8, означает, что документ выведен из недействительного источника.
4. Заморозка источника **не запрещает** его изменение. Она гарантирует, что изменение будет замечено.

Без закрепления версий возникает самый незаметный дефект производства: документ выводится из источника, который менялся, пока документ писали.

## 6.10. Спецификации стадий

Далее — по девять полей на каждую стадию. Порядок полей одинаков и не меняется.

---

### P0 · Запрос

| | |
|---|---|
| **Назначение** | Установить, что документ вообще нужен, и зафиксировать, чей спрос он удовлетворяет |
| **Входы** | Потребность: нерешённый вопрос, повторяющееся разногласие, требование вышестоящего документа, обнаруженный пробел |
| **Выходы** | Заявка на производство: потребность, кто её носитель, что сломано без документа |
| **Валидация** | Потребность сформулирована как вопрос без ответа. Указан носитель потребности. Указано последствие отсутствия документа |
| **Ответственная роль** | Инициатор — любая роль |
| **Участие AI** | ДОПУСКАЕТСЯ: обнаружение пробелов в корпусе, поиск повторяющихся разногласий, оформление заявки. НЕ ДОПУСКАЕТСЯ: порождать потребность самостоятельно |
| **Критерии рецензии** | Потребность реальна, а не выведена из симметрии структуры. «Здесь должен быть документ, потому что у соседнего слоя такой есть» — не потребность |
| **Условия отказа** | Потребность не сформулирована как вопрос. Носитель отсутствует. Потребность закрывается существующим документом |
| **Восстановление** | R6 при отсутствии потребности; R1 к переформулированию |

---

### P1 · Область

| | |
|---|---|
| **Назначение** | Зафиксировать единственный вопрос документа, его зону, владельца и критерии завершённости |
| **Входы** | Заявка P0; структура корпуса; реестр владения понятиями |
| **Выходы** | Карта области = заявка на создание по DES-002, раздел 6.10, включая правила валидации будущего документа |
| **Валидация** | Условия входа E0–E8 (DES-002) выполнены полностью |
| **Ответственная роль** | Владеющая роль зоны; при новом слое — держатель реестра |
| **Участие AI** | ДОПУСКАЕТСЯ: проверка E0 по корпусу, поиск конкурирующих владельцев понятий, черновик карты. НЕ ДОПУСКАЕТСЯ: утверждать область, назначать владельца |
| **Критерии рецензии** | Вопрос — один и без союза «и». Ни одно заявляемое понятие не занято. Все источники в том же или вышестоящем слое. Правила завершённости проверяемы «да / нет» |
| **Условия отказа** | E0 даёт утвердительный ответ. Понятие занято. Источники ниже по течению. Правила завершённости неформулируемы |
| **Восстановление** | R6 при утвердительном E0; R3 при двух вопросах; R5 при споре о владении понятием |
| **Ворота** | **жёсткие** |

---

### P2 · Источники

| | |
|---|---|
| **Назначение** | Собрать и проверить всё, из чего документ будет выведен, и обнаружить, чего не хватает — до того, как это обнаружится в прозе |
| **Входы** | Карта области P1 |
| **Выходы** | Досье источников: перечень с закреплёнными версиями, состояниями, оценкой достаточности; перечень пробелов |
| **Валидация** | Каждый источник существует и находится в состоянии не ниже `Approved`. Версия каждого закреплена. Каждый пробел зарегистрирован как открытый вопрос |
| **Ответственная роль** | Автор; подтверждает владеющая роль |
| **Участие AI** | **Основная зона пользы.** ДОПУСКАЕТСЯ: сбор источников, проверка состояний и версий, обнаружение пробелов, выявление расхождений между источниками. НЕ ДОПУСКАЕТСЯ: восполнять пробел правдоподобным содержанием (DES-008, N2) |
| **Критерии рецензии** | Источники достаточны для всех предполагаемых утверждений. Ни один источник не в состоянии `Draft` или `Disputed`. Пробелы объявлены, а не обойдены |
| **Условия отказа** | Источник в состоянии ниже `Approved`. Источники противоречат друг другу. Источников недостаточно для заявленной области |
| **Восстановление** | R4 при пробеле, требующем внешнего ответа; R5 при расхождении источников (DES-009); R2 при недостаточности источников для части области |
| **Ворота** | мягкие — при объявленных пробелах производство продолжается, пробелы становятся гипотезами |

---

### P3 · Утверждения

| | |
|---|---|
| **Назначение** | Перечислить всё, что документ намерен утверждать, и утвердить этот перечень — **главные ворота конвейера** |
| **Входы** | Карта области P1; досье источников P2 |
| **Выходы** | Реестр утверждений (раздел 6.6) с состоянием каждой строки |
| **Валидация** | Каждое утверждение — одно предложение. Каждое имеет класс и источник. Ни одно не выходит за зону документа. Каждое понятие из карты области покрыто хотя бы одним утверждением |
| **Ответственная роль** | Автор составляет; **владеющая роль утверждает** |
| **Участие AI** | **Основная зона пользы.** ДОПУСКАЕТСЯ: извлечение утверждений из источников, классификация, проставление источников, обнаружение утверждений без источника и дублирующих чужие. НЕ ДОПУСКАЕТСЯ: утверждать реестр; добавлять утверждения, не выводимые из досье |
| **Критерии рецензии** | Рамка верна: документ утверждает то, что должен. Ни одно утверждение не принадлежит другому документу. Ни одно не выведено из гипотезы. Покрытие зоны полное — нет умолчаний, которые придётся дописывать в прозе |
| **Условия отказа** | Утверждение без источника. Утверждение вне зоны. Рецензент не согласен с рамкой. Реестр не покрывает заявленные понятия |
| **Восстановление** | R1 к P2 при недостатке источников; R1 к P1 при несогласии с рамкой; R3 при обнаружении второго вопроса; R5 при споре о владении утверждением |
| **Ворота** | **жёсткие.** Стадия P5 не открывается при частично утверждённом реестре |

### P4 · Структура

| | |
|---|---|
| **Назначение** | Разложить утверждённые утверждения по разделам и создать файл документа со всем контрактом, кроме содержания |
| **Входы** | Реестр утверждений P3 |
| **Выходы** | Файл документа в состоянии `Scaffold`: метаданные, разделы 1–5, пустой раздел 6, соответствие «раздел → утверждения» |
| **Валидация** | Каждое утверждение отнесено ровно к одному разделу. Каждый раздел содержит хотя бы одно утверждение. Метаданные полны. Глубина разделов ≤ 3. Бюджет ответственности не превышен (DES-010) |
| **Ответственная роль** | Автор |
| **Участие AI** | ДОПУСКАЕТСЯ: раскладка утверждений по разделам, порождение скелета, заполнение вычислимых метаданных, проверка бюджета. НЕ ДОПУСКАЕТСЯ: изменять формулировки утверждений при раскладке |
| **Критерии рецензии** | Раздел, не содержащий утверждений, — лишний. Утверждение, не помещающееся ни в один раздел, означает неверную структуру, а не потребность в новом разделе |
| **Условия отказа** | Утверждение не относится однозначно ни к одному разделу. Бюджет ответственности превышен. Требуется более трёх уровней вложенности |
| **Восстановление** | R1 к P3 при неоднозначной раскладке; R3 при превышении бюджета |
| **Ворота** | мягкие |

### P5 · Черновик

| | |
|---|---|
| **Назначение** | Изложить утверждённые утверждения связной прозой. Единственная стадия, на которой пишется содержание |
| **Входы** | Скелет P4; реестр утверждений P3; правила диаграмм, примеров и терминов |
| **Выходы** | Документ в состоянии `Draft` с заполненным разделом 6 и таблицей вывода |
| **Валидация** | Каждое утверждение реестра изложено. Ни одно утверждение вне реестра не введено. Таблица вывода соответствует реестру. Термины употреблены в зарегистрированных значениях |
| **Ответственная роль** | Автор |
| **Участие AI** | **ДОПУСКАЕТСЯ полностью.** Изложение утверждённых утверждений — изменение класса B (DES-008): суждение уже израсходовано на P3. НЕ ДОПУСКАЕТСЯ: вводить утверждения, отсутствующие в реестре, даже верные и уместные |
| **Критерии рецензии** | Проза не добавляет и не убавляет утверждений. Ни одно правило не оказалось только в диаграмме или примере. Пояснения не несут нормы |
| **Условия отказа** | Введено утверждение вне реестра. Утверждение реестра не изложено. Норма оказалась в диаграмме или примере |
| **Восстановление** | R1 к P3 при обнаружении необходимого утверждения, отсутствующего в реестре — **добавление в прозу НЕ ДОПУСКАЕТСЯ** |
| **Ворота** | мягкие |

**Ключевое следствие стадии.** Обнаружив по ходу изложения нужное утверждение, автор не дописывает его. Он возвращается на P3. Это медленнее в моменте и дешевле в сумме: утверждение, добавленное в прозу, минует все ворота и остаётся непрослеженным.

### P6 · Самопроверка

| | |
|---|---|
| **Назначение** | Исчерпать всё, что автор способен проверить сам, чтобы рецензент тратил внимание только на смысл |
| **Входы** | Черновик P5 |
| **Выходы** | Отчёт самопроверки (DES-004, раздел 6.7) с обязательным перечнем непроверенного; запрос на переход в `Review` |
| **Валидация** | Уровни V1 и V2 пройдены. Чек-лист CR1–CR14 пройден. Условия выхода X1–X4, X8–X12 проверены. Перечень непроверенного составлен |
| **Ответственная роль** | Автор |
| **Участие AI** | **Основная зона пользы.** ДОПУСКАЕТСЯ: выполнение всех автоматизируемых проверок, сверка прозы с реестром утверждений, сверка таблицы вывода, проверка терминов, вычисление зоны влияния. НЕ ДОПУСКАЕТСЯ: объявлять проверку пройденной без результата |
| **Критерии рецензии** | Отчёт содержит доказательства, а не утверждения (DES-003, раздел 6.5). Перечень непроверенного непуст по умолчанию |
| **Условия отказа** | Провал V1 или V2. Расхождение прозы с реестром утверждений. Отчёт без доказательств |
| **Восстановление** | R1 к P5 при дефектах изложения; R1 к P4 при дефектах структуры; R1 к P2 при устаревшем источнике |
| **Ворота** | жёсткие для V1 и V2 |

### P7 · Рецензия

| | |
|---|---|
| **Назначение** | Независимо подтвердить, что документ решает задачу, а не только соответствует форме |
| **Входы** | Документ в `Review`; отчёт P6; реестр утверждений; карта области |
| **Выходы** | Вердикт: принято / отклонено с указанием условия и места; при принятии — переход в `Approved` |
| **Валидация** | Условия выхода X1–X12 полностью (DES-003). Рецензент независим от автора |
| **Ответственная роль** | Рецензент, независимый от автора; при авторстве AI — **обязательно человек** |
| **Участие AI** | ДОПУСКАЕТСЯ: подготовка материалов рецензенту, повторное выполнение проверок, указание на расхождения. **НЕ ДОПУСКАЕТСЯ выносить вердикт** (DES-008, N4) |
| **Критерии рецензии** | Документ отвечает на вопрос карты области. Каждое утверждение прослежено. Ничего сверх зоны. Уровень V3 проверен полностью по изменённому содержанию |
| **Условия отказа** | Любое из X1–X12 не выполнено. Несогласие с рамкой. Обнаружен конфликт с другим документом |
| **Восстановление** | R1 к стадии, породившей дефект — **не к P5 по умолчанию**; R5 при конфликте (DES-009); действует правило двух возвратов |
| **Ворота** | **жёсткие** |

**Правило адресации отказа.** Отказ возвращает на стадию, где дефект **возник**, а не на предыдущую. Несогласие с рамкой — на P3. Нехватка источника — на P2. Неверная зона — на P1. Возврат «на доработку» без указания стадии не является отказом: он не проверяем и порождает колебание.

### P8 · Интеграция

| | |
|---|---|
| **Назначение** | Встроить принятый документ в корпус: каскад, ссылки, реестры |
| **Входы** | Документ в `Approved`; вычисленная зона влияния (DES-006, раздел 6.6) |
| **Выходы** | Запись интеграции: каждый документ каскада с исходом; обновлённые реестры; отметки проверки каскада |
| **Валидация** | Каждый документ прямого влияния имеет зафиксированный исход. Симметрия связей сохранена. Реестры обновлены. Ни один источник не изменился с момента P2 |
| **Ответственная роль** | Автор; проверяет держатель реестра |
| **Участие AI** | **Основная зона пользы.** ДОПУСКАЕТСЯ: вычисление зоны влияния, обход каскада, проверка симметрии, обновление отметок, обнаружение несовпадения версий источников. НЕ ДОПУСКАЕТСЯ: разрешать обнаруженные противоречия (DES-008, N3) |
| **Критерии рецензии** | Каскад обойдён целиком, а не выборочно. Исход «не затронут» подтверждён прочтением, а не предположением |
| **Условия отказа** | Источник изменился с момента закрепления на P2. Документ каскада противоречит новому. Каскад обойдён частично |
| **Восстановление** | R1 к P2 или P3 при изменении источника; R5 при противоречии в каскаде |
| **Ворота** | жёсткие |

### P9 · Канонизация

| | |
|---|---|
| **Назначение** | Зарегистрировать документ как единственный источник по его понятиям |
| **Входы** | Документ в `Approved`; запись интеграции P8 |
| **Выходы** | Строки в реестре владения понятиями и реестре порядка чтения; переход в `Canonical` |
| **Валидация** | Каждое понятие зарегистрировано и не занято другим документом. Все зависимости в состоянии `Canonical`. Гипотез в нормативной части нет |
| **Ответственная роль** | **Держатель реестра** |
| **Участие AI** | ДОПУСКАЕТСЯ: проверка условий, подготовка строк реестров. **НЕ ДОПУСКАЕТСЯ выполнять переход** (DES-008, N4) |
| **Критерии рецензии** | Конкурирующих владельцев нет. Каноничность распространяется от корня графа наружу |
| **Условия отказа** | Понятие заявлено другим документом. Зависимость не `Canonical`. В нормативной части остались гипотезы |
| **Восстановление** | R5 при конкуренции за понятие; R4 при незакрытой гипотезе; ожидание при неканоничной зависимости — документ остаётся в `Approved`, что является штатным состоянием |
| **Ворота** | **жёсткие** |

### 6.11. Повторный вход при изменении

Изменение существующего документа — не новое производство. Оно входит в конвейер на стадии, соответствующей классу изменения.

| Класс изменения | Точка входа | Обязательные стадии |
|-----------------|-------------|---------------------|
| `PATCH` — формулировка, ссылка | P5 | P5, P6 |
| `MINOR` — новое утверждение | **P3** | P3, P4, P5, P6, P8 |
| `MAJOR` — изменение или отмена утверждения | **P2** | P2, P3, P4, P5, P6, P7, P8, P9 |
| Изменение зоны документа | **P1** | весь конвейер |

**Правило входа `MINOR`.** Добавление содержания входит на P3, а не на P5. Новое утверждение проходит те же ворота, что и первоначальные, — иначе зона документа расширяется серией мелких дополнений, ни одно из которых не проверялось (DES-010, раздел 6.8).

### 6.12. Сокращённый конвейер

Полный конвейер оправдан не всегда. Сокращение ДОПУСКАЕТСЯ по правилам:

1. Сокращается **объём** стадии, а не их перечень.
2. Стадии P1, P3, P7, P9 НЕ ДОПУСКАЮТСЯ к сокращению ни при каких условиях: на них принимаются решения.
3. Для документа, производимого одной ролью в один приём, артефакты P0–P2 ДОПУСКАЕТСЯ объединять в одну запись.
4. Реестр утверждений НЕ ДОПУСКАЕТСЯ к сокращению даже для короткого документа: именно он предотвращает переписывание.
5. Сокращение фиксируется в заявке. Несокращаемая стадия, пройденная формально, — отклонение (DES-016, раздел 6.6).

### 6.13. Как конвейер устраняет переписывание

| Причина переписывания | Где перехвачена |
|-----------------------|-----------------|
| Область изменилась после написания | ворота P1, до существования файла |
| Источник отсутствует или недействителен | ворота P2, до формулирования утверждений |
| Рецензент не согласен с рамкой | ворота P3, до написания прозы |
| Утверждение отклонено | ворота P3, ценой одной строки |
| Структуру пришлось перекомпоновать | ворота P4, до написания прозы |
| Источник изменился, пока писали | закрепление версий P2, обнаружение P8 |
| Зона расползлась дополнениями | правило входа `MINOR` на P3 |
| Колебание между стадиями | правило двух возвратов |
| Норма попала в диаграмму или пример | критерии рецензии P5 |

Единственное, что конвейер не устраняет, — переписывание из-за изменения самой предметной области. Это не дефект: оно и должно приводить к переработке.

### 6.14. Участие AI по стадиям

| Стадия | Роль агента |
|--------|-------------|
| P0 | оформление; обнаружение пробелов |
| P1 | проверка E0; **решение — за ролью** |
| P2 | **сбор и проверка источников — основная польза** |
| P3 | **извлечение и классификация утверждений — основная польза**; утверждение — за ролью |
| P4 | раскладка и порождение скелета |
| P5 | **изложение — допускается полностью** |
| P6 | **проверки — основная польза** |
| P7 | подготовка материалов; **вердикт — за человеком** |
| P8 | **каскад и реестры — основная польза** |
| P9 | проверка условий; **переход — за держателем реестра** |

**Почему изложение поручается агенту безопасно.** К стадии P5 всё, что требует суждения, уже израсходовано: область утверждена на P1, источники проверены на P2, утверждения приняты на P3. Проза, порождённая из утверждённого реестра, не может внести непроверенное утверждение — а если вносит, это обнаруживается сверкой прозы с реестром на P6.

Конвейер, таким образом, решает не только задачу переписывания. Он переводит участие AI из самого рискованного места производства — свободного написания — в места, где агент силён и где его ошибка обнаружима.
