# Условия входа — создание документа

> Самый дешёвый способ получить противоречие — создать документ. Самый дешёвый способ его избежать — не создавать.
>
> Этот документ задаёт барьер, который новый файл ОБЯЗАН преодолеть, прежде чем появиться.

---

## 1. Purpose · Назначение

Не допустить появления документов, которые дублируют существующее знание, не имеют владельца, не имеют источника или не имеют определения завершённости.

## 5. Validation Rules · Правила валидации

1. Каждое условие E0–E8 проверяемо ответом «да / нет» до написания содержания.
2. Ни одно условие не требует прочтения содержания создаваемого документа.
3. Тест раздела 6.1 даёт отрицательный результат для каждого существующего документа корпуса.

## 6. Content · Содержание

### 6.1. E0 · Тест на ненужность

Выполняется первым. Документ НЕ ДОПУСКАЕТСЯ создавать, пока хотя бы один ответ утвердительный.

| # | Вопрос | Если «да» |
|---|--------|-----------|
| E0.1 | Существует ли документ, отвечающий на **тот же** вопрос? | писать туда |
| E0.2 | Существует ли документ, отвечающий на **соседний** вопрос, у которого есть запас бюджета ответственности (DES-010)? | расширить его |
| E0.3 | Является ли новое знание **применением** существующего правила к частному случаю? | это не документ, а ссылка на правило |
| E0.4 | Является ли новое знание **пересказом** того, на что можно сослаться? | заменить ссылкой |
| E0.5 | Создаётся ли документ потому, что искать существующий дольше, чем написать новый? | найти существующий |

E0.5 — самая частая настоящая причина дублирования. Она формулируется явно, потому что в обосновании создания её никогда не пишут.

### 6.2. E1 · Единственный вопрос

Документ ОБЯЗАН отвечать ровно на **один** вопрос, формулируемый одним предложением без союза «и».

| Форма | Оценка |
|-------|--------|
| «На какой вопрос отвечает документ?» → одно предложение, один вопрос | принимается |
| Формулировка содержит «и», «а также», «включая» | отклоняется: это два документа |
| Формулировка описывает **тему**, а не вопрос | отклоняется: тема не задаёт границы |

Разница существенна: тема расползается, вопрос — нет. «Про уведомления» — тема. «Когда система обращается к пользователю вне приложения» — вопрос.

### 6.3. E2 · Заявка на владение понятиями

Документ ОБЯЗАН заранее перечислить понятия, которыми будет владеть, и понятия, которыми владеть не будет.

1. Список владения ОБЯЗАН быть непустым. Документ, не владеющий ничем, дублирует что-то другое.
2. Ни одно заявленное понятие НЕ ДОПУСКАЕТСЯ, если оно уже зарегистрировано за другим документом.
3. Конфликт заявки разрешается **до** создания: либо понятие переходит новому документу с миграцией (DES-015), либо документ не создаётся.
4. Список исключений (чем документ владеть не будет) ОБЯЗАН перечислять смежные зоны с указанием их владельцев. Он защищает от расползания.

### 6.4. E3 · Источники вывода

Документ ОБЯЗАН заранее указать, из чего выводится его содержание.

| Класс документа | Требование к источникам |
|-----------------|-------------------------|
| **Производный** | ОБЯЗАН указать ≥ 1 вышестоящий авторитетный документ |
| **Документ факта** | ОБЯЗАН указать внешний источник наблюдения и способ подтверждения |
| **Документ решения** | ОБЯЗАН указать решение, которое фиксирует |
| **Определяющий** | ОБЯЗАН указать документ, из которого берётся необходимость определения |

Документ без источников не создаётся. Отсутствие источника означает, что содержание будет придумано, а не выведено (DES-006).

### 6.5. E4 · Размещение

Документ ОБЯЗАН иметь место в структуре, определённой привязкой, **до** создания.

1. Указан слой (зона) и обоснование выбора: вопрос документа совпадает с вопросом слоя.
2. Проверено направление зависимостей: все источники находятся в том же или вышестоящем слое.
3. Источник в нижестоящем слое — признак того, что документ создаётся не на своём уровне. Создание НЕ ДОПУСКАЕТСЯ до пересмотра размещения.

### 6.6. E5 · Владелец

1. Назначена ровно одна владеющая **роль** (DES-007). Не человек.
2. Роль существует в каталоге ролей привязки.
3. Роль подтвердила принятие владения. Документ, назначенный роли без её ведома, остаётся бесхозным с первого дня.

### 6.7. E6 · Место в порядке чтения

1. Определена позиция в каноническом порядке чтения.
2. Позиция расположена после всех источников документа.
3. Позиция не нарушает порядок существующих документов.

### 6.8. E7 · План регистрации

Перечислены реестры, обновляемые **в том же изменении**, что и создание:

- реестр порядка чтения;
- реестр владения понятиями;
- реестр идентификаторов, если документ вводит новые;
- обратные ссылки в документах-источниках (симметрия зависимостей).

Отложенная регистрация НЕ ДОПУСКАЕТСЯ: документ, существующий вне реестров, невидим для проверок корпуса и потому неуправляем.

### 6.9. E8 · Критерии завершённости раньше содержания

**Ключевое требование стандарта.**

Документ ОБЯЗАН содержать собственные правила валидации (раздел «Validation Rules») **до** написания содержания.

Обоснование: пока содержание не написано, критерий завершённости формулируется от задачи. После — от написанного. Второе бесполезно: любой текст удовлетворяет критерию, выведенному из него самого.

Требования к правилам:

1. Каждое правило проверяемо ответом «да / нет».
2. Каждое правило может быть нарушено. Правило, нарушить которое невозможно, удаляется как бессодержательное.
3. Правила покрывают все понятия из заявки на владение (E2).
4. Число правил СЛЕДУЕТ удерживать в пределах 3–8: меньше — не покрывают, больше — признак превышения бюджета ответственности (DES-010).

### 6.10. Заявка на создание

Создание документа оформляется заявкой. Заявка ОБЯЗАНА содержать:

```
Вопрос документа:        <одно предложение, без «и»>
Класс:                   производный | факта | решения | определяющий
Заявка на владение:      <перечень понятий>
Не владеет:              <смежные зоны и их владельцы>
Источники:               <перечень вышестоящих документов / внешних источников>
Слой:                    <зона по привязке>
Владеющая роль:          <роль; подтверждение получено: да/нет>
Позиция чтения:          <позиция>
Реестры к обновлению:    <перечень>
Правила завершённости:   <3–8 проверяемых правил>
Результат E0:            <ответы E0.1–E0.5, все отрицательные>
```

Заявка сохраняется. При последующем споре о зоне документа она является свидетельством исходного намерения.

### 6.11. Кто пропускает

| Класс документа | Кто разрешает создание |
|-----------------|------------------------|
| Внутри существующего слоя | владеющая роль слоя |
| Новый слой или зона | держатель реестра + записанное решение |
| Документ решения | роль, принимающая решения |
| Предложено AI-агентом | ОБЯЗАТЕЛЬНО человек (DES-008) |

AI-агент ДОПУСКАЕТСЯ к подготовке заявки, но НЕ ДОПУСКАЕТСЯ к её утверждению.

### 6.12. Что не является основанием для создания

| Основание | Почему отклоняется |
|-----------|--------------------|
| «Документ слишком длинный» | длина не критерий; см. DES-010 |
| «Тема логически отдельная» | логическая отдельность ≠ отдельный вопрос |
| «Так удобнее читать» | решается порядком чтения и оглавлением |
| «Другой команде нужен свой» | ведёт к двум источникам одного знания; решается ссылкой |
| «Пока черновик, потом объединим» | объединение не происходит; создаётся дубликат |
| «Это временно» | временных документов не бывает |
