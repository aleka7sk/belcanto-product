# Декомпозиция и слияние документов

> Разделение документа — операция над корпусом, а не над файлом. Оно затрагивает входящие ссылки, владение понятиями, порядок чтения и каскады.
>
> Выполненное как правка, оно оставляет за собой битые ссылки и понятия без владельца. Выполненное как процедура — не оставляет ничего.

---

## 1. Purpose · Назначение

Задать, когда документ подлежит разделению, по какой границе он делится и как разделение выполняется без потери связности корпуса.

## 6. Content · Содержание

### 6.1. Основания для разделения

Документ подлежит разделению при выполнении любого условия:

| # | Основание | Измерение (DES-010) |
|---|-----------|---------------------|
| S1 | Документ отвечает более чем на один вопрос | M2 > 1 |
| S2 | Разделами владеют разные роли | M3 > 1 |
| S3 | Части документа не меняются вместе | M6 ниже порога |
| S4 | Части документа выводятся из разных слоёв | M8, признак P8 |
| S5 | Части документа меняются с существенно разной частотой | M5 |
| S6 | Разные потребители ссылаются на непересекающиеся части | M8 |
| S7 | Наблюдаются два и более признака перегрузки | раздел 6.4 DES-010 |

### 6.2. Стратегии разделения

Стратегия определяет **границу**. Выбор стратегии важнее самого решения делить: неверная граница создаёт два документа, каждый из которых по-прежнему перегружен.

| # | Стратегия | Граница | Когда применима |
|---|-----------|---------|-----------------|
| **D1 · По вопросу** | каждый вопрос — отдельный документ | S1 | основная стратегия; применяется первой |
| **D2 · По владельцу** | зона ответственности роли | S2 | вопросы близки, но ответственность разная |
| **D3 · По скорости изменения** | устойчивое отделяется от изменчивого | S3, S5 | принципы отдельно от параметров |
| **D4 · По уровню вывода** | утверждения разных слоёв | S4 | смешение уровней |
| **D5 · Реестр и описания** | перечень отдельно от описаний записей | реестр разросся описаниями | каталоги, справочники |
| **D6 · По аудитории** | документ на класс читателей | S6 | только если аудитории читают непересекающиеся части |

**Приоритет.** Сначала проверяется D1. Разделение по любой другой границе при невыполненном D1 оставит оба потомка отвечающими на несколько вопросов.

**D3 заслуживает отдельного внимания.** Разделение устойчивого и изменчивого — самый недооценённый приём: он сохраняет стабильность ссылок на принципы, позволяя параметрам меняться часто и независимо.

### 6.3. Антипаттерны

| # | Антипаттерн | Почему вреден |
|---|-------------|---------------|
| X1 | Разделение по объёму | даёт два документа, отвечающих на половину вопроса каждый |
| X2 | Разделение по главам | сохраняет одну ответственность, размазанную по файлам |
| X3 | Разделение «часть 1 / часть 2» | граница не смысловая; потомки не имеют собственных вопросов |
| X4 | Потомок без собственного владения понятиями | документ, не владеющий ничем, дублирует другой |
| X5 | Разделение с сохранением содержания в родителе | создаёт два источника одного знания |
| X6 | Разделение без перенаправления входящих ссылок | оставляет читателя на устаревшем адресе |
| X7 | Разделение вместо удаления лишнего | перегрузка часто вызвана содержанием, которого не должно быть нигде |

X7 проверяется первым: перед разделением СЛЕДУЕТ убедиться, что перегрузка не создана содержанием, принадлежащим другому документу или не принадлежащим корпусу вовсе.

### 6.4. Процедура разделения

```
1. ОБОСНОВАТЬ
   Указать основание S1–S7 и подтверждающее измерение.

2. ВЫБРАТЬ СТРАТЕГИЮ
   Указать стратегию D1–D6 и границу разделения.

3. РАСПРЕДЕЛИТЬ ПОНЯТИЯ
   Каждое понятие исходного документа отнести ровно к одному потомку.
   Понятие, не относимое однозначно, означает неверную границу — вернуться к шагу 2.

4. РАСПРЕДЕЛИТЬ ИСТОЧНИКИ
   Каждая строка таблицы вывода относится к одному потомку.
   Потомок без источников недопустим (DES-002, E3).

5. СОЗДАТЬ ПОТОМКОВ
   Каждый потомок проходит условия входа DES-002 полностью,
   включая собственные правила валидации.
   Каждый потомок получает владельца явно (DES-007).

6. ОПРЕДЕЛИТЬ СУДЬБУ РОДИТЕЛЯ
   См. раздел 6.5.

7. ПЕРЕНАПРАВИТЬ ВХОДЯЩИЕ ССЫЛКИ
   Каждая входящая ссылка ведётся к нужному потомку, а не к родителю.
   Ссылка на раздел — к соответствующему разделу потомка.

8. ОБНОВИТЬ РЕЕСТРЫ
   Порядок чтения, владение понятиями, идентификаторы.

9. ЗАПИСАТЬ МИГРАЦИЮ
   Разделение регистрируется как миграция класса M-D (DES-015).

10. ПРОВЕРИТЬ
    Чек-листы DES-004 и DES-005 для всех потомков и для родителя.
```

Шаги 3 и 7 — места, где процедура чаще всего обрывается. Шаг 3 обрывается, потому что распределение понятий выявляет неверную границу и требует возврата. Шаг 7 обрывается, потому что он выполняется вне изменяемых файлов.

### 6.5. Судьба исходного документа

| Вариант | Когда | Что остаётся |
|---------|-------|--------------|
| **Указатель** | прежний адрес остаётся ожидаемым для читателей | назначение и перечень потомков; знания нет |
| **Обзор** | потомкам нужна общая точка входа | назначение, связи между потомками, порядок чтения; знания нет |
| **Выведен из обращения** | прежний адрес не имеет ценности | состояние `Superseded` со ссылками на потомков |

Во всех вариантах родитель НЕ ДОПУСКАЕТСЯ сохраняющим содержание, распределённое между потомками. Иначе разделение создаёт ровно ту проблему, ради которой выполнялось.

### 6.6. Атомарность

Разделение ОБЯЗАНО выполняться одним изменением, включающим:

- всех потомков;
- изменённого или выведенного из обращения родителя;
- все перенаправленные входящие ссылки;
- обновлённые реестры;
- запись миграции.

Разделение, растянутое на несколько изменений, оставляет корпус в состоянии, где одно понятие принадлежит двум документам или ни одному.

### 6.7. Слияние

Слияние — обратная операция. Основания:

| # | Основание |
|---|-----------|
| J1 | Документы отвечают на один и тот же вопрос |
| J2 | Документы всегда меняются вместе |
| J3 | Ни один документ не имеет собственного владения понятиями |
| J4 | Один документ является пересказом другого |
| J5 | Разделение выполнено по антипаттерну X1–X3 |

Процедура:

```
1. Подтвердить, что вопрос действительно один (DES-010, раздел 6.2).
2. Определить владельца объединённого документа ДО слияния.
   Владелец не определяется → документы сливать НЕ ДОПУСКАЕТСЯ.
3. Объединить понятия, источники и правила валидации.
4. Проверить бюджет ответственности объединённого документа (DES-010).
   Бюджет превышен → слияние отменяется.
5. Перенаправить входящие ссылки обоих документов.
6. Исходные документы перевести в Superseded со ссылкой на объединённый.
7. Обновить реестры, записать миграцию класса M-D.
```

Шаг 4 существен: слияние двух корректных документов часто даёт один перегруженный.

### 6.8. Сохранение истории

1. Потомки ОБЯЗАНЫ указывать документ-предшественник и его версию на момент разделения.
2. Родитель, выведенный из обращения, ОБЯЗАН перечислять всех потомков.
3. История изменений НЕ ДОПУСКАЕТСЯ к удалению при разделении: она дублируется в каждого потомка с пометкой о происхождении.
4. Запись миграции содержит соответствие «раздел родителя → документ-потомок» и служит картой для тех, кто вернётся к прежним ссылкам.
