# Domain Overview

> Данный документ описывает предметную область Belcanto Product.
>
> Его задача — определить основные понятия, которыми оперирует система.
>
> Все остальные доменные документы должны использовать терминологию, определенную здесь.

---

# Что такое Domain

Domain — это описание реального мира школы Belcanto.

Он отвечает не на вопрос

> Как устроен код?

а на вопрос

> Как устроен бизнес?

---

# Главная идея

Belcanto Product не строится вокруг экранов.

Он строится вокруг предметной области.

Поэтому сначала определяются бизнес-сущности.

И только потом появляются:

- API
- База данных
- Интерфейсы
- Backend
- Mobile

---

# Основные сущности

На текущий момент предметная область включает следующие понятия.

---

## Student

Человек, проходящий обучение.

Student является центральной сущностью системы.

Практически все остальные объекты связаны со Student.

---

## Teacher

Преподаватель школы.

Teacher сопровождает развитие Student.

---

## Lesson

Конкретное занятие между преподавателем и учеником.

Lesson имеет собственную историю.

---

## Homework

Домашнее задание.

Создается преподавателем.

Связано с Lesson.

---

## Skill

Навык ученика.

Например:

- дыхание
- дикция
- интонация
- чувство ритма

Skill развивается постепенно.

---

## Assessment

Педагогическая оценка.

Assessment описывает мнение преподавателя.

Это не школьная оценка.

---

## Goal

Цель обучения.

Goal помогает понять, зачем ученик занимается.

---

## Song

Музыкальное произведение.

Используется как инструмент развития.

---

## Concert

Событие, во время которого ученики выступают.

Concert является частью образовательного процесса.

---

## Achievement

Зафиксированный результат.

Achievement отражает достижения ученика.

---

## Progress

История изменений.

Progress показывает развитие ученика во времени.

---

## Event

Любое значимое событие.

Например:

- урок проведен
- домашнее задание создано
- концерт завершен

Практически все изменения системы представлены событиями.

---

## Schedule

Расписание занятий.

---

## Notification

Уведомление пользователю.

---

## Comment

Комментарий преподавателя.

---

## Attachment

Файл.

Например:

- фотография
- видео
- запись исполнения
- PDF

---

# Главный объект

Центром предметной области является Student.

Все остальные сущности существуют для сопровождения его развития.

```
                 Student
                     │
      ┌──────────────┼──────────────┐
      │              │              │
   Lesson         Progress       Teacher
      │              │
      │              │
 Homework        Assessment
      │              │
      │              │
    Song          Skill
      │              │
      └─────── Concert ───────┘
```

---

# Общие правила

Все сущности должны:

иметь уникальный идентификатор;

иметь историю изменений;

иметь автора изменений (если применимо);

иметь дату создания;

иметь понятный жизненный цикл.

---

# Что НЕ является Domain

Следующее не относится к предметной области.

- SQL
- таблицы
- REST API
- GraphQL
- protobuf
- Redis
- PostgreSQL
- Flutter
- Go
- React

Это детали реализации.

---

# Domain First

При проектировании необходимо соблюдать следующий порядок.

```
Domain

↓

Business Rules

↓

Events

↓

Commands

↓

State Machine

↓

API

↓

Database

↓

UI
```

Нарушение данного порядка допускается только по архитектурному решению.

---

# Domain Invariants

Предметная область должна оставаться стабильной.

Технологии могут меняться.

Мобильное приложение может меняться.

Backend может быть переписан.

Но понятия:

Student

Lesson

Teacher

Skill

Assessment

остаются неизменными.
