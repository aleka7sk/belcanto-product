# Что такое Domain

Domain — это описание реального мира школы Belcanto.

Он отвечает не на вопрос

> Как устроен код?

а на вопрос

> Как устроен бизнес?

---

# Главная идея

Belcanto Product не строится вокруг экранов.

Он строится вокруг предметной области.

Поэтому сначала определяются бизнес-сущности.

И только потом появляются:

- API
- База данных
- Интерфейсы
- Backend
- Mobile

---

# Структурный каталог · не словарь

Канонические имена и определения берутся из
`language/001-ubiquitous-language.md`. Записи ниже показывают только модельные
границы B.0 и не создают второго определения.

| Структура | Ответственность Domain |
|-----------|-------------------------|
| `Person` | отдельная идентичность человека, на которую ссылаются остальные структуры |
| `SchoolMembership` | отдельная связь `Person` со школьным контекстом |
| `Student` | учебная идентичность и её история, независимые от цифрового доступа |
| `Account` | состояние цифрового доступа, парольные данные и сессии |
| `Invitation` | жизненный цикл персонального права активации `Account` |
| `DelegatedSuperadminAccess` | отзывное разрешение `Administrator` создавать Student и читать onboarding; не включает Invitation и не является ролью или персоной |

Унаследованные структурные имена `Teacher`, `Lesson`, `Homework`, `Skill`,
`Assessment`, `Goal`, `Song`, `Concert`, `Achievement`, `Progress`, `Event`,
`Schedule`, `Notification`, `Comment` и `Attachment` сохраняются в действующих
документах для совместимости. Настоящий обзор больше не определяет их смысл;
новая производная проза не может использовать эти старые описания как словарь
до отдельной утверждённой терминологической партии.

# Главный объект

Центром предметной области является Student.

Все остальные сущности существуют для сопровождения его развития.

```
                 Student
                     │
      ┌──────────────┼──────────────┐
      │              │              │
   Lesson         Progress       Teacher
      │              │
      │              │
 Homework        Assessment
      │              │
      │              │
    Song          Skill
      │              │
      └─────── Concert ───────┘
```

---

# Общие правила

Все сущности должны:

иметь уникальный идентификатор;

иметь историю изменений;

иметь автора изменений (если применимо);

иметь дату создания;

иметь понятный жизненный цикл.

---

# Что НЕ является Domain

Следующее не относится к предметной области.

- SQL
- таблицы
- REST API
- GraphQL
- protobuf
- Redis
- PostgreSQL
- Flutter
- Go
- React

Это детали реализации.

---

# Domain First

При проектировании необходимо соблюдать следующий порядок.

```
Domain

↓

Business Rules

↓

Events

↓

Commands

↓

State Machine

↓

API

↓

Database

↓

UI
```

Нарушение данного порядка допускается только по архитектурному решению.

---

# Domain Invariants

Предметная область должна оставаться стабильной.

Технологии могут меняться.

Мобильное приложение может меняться.

Backend может быть переписан.

Но понятия:

Student

Lesson

Teacher

Skill

Assessment

остаются неизменными.
